# 데이터 카탈로그

기존 dbt 문서에 모델의 의미, 테이블 계보, 품질 규칙과 실행 기록을 연결했다. 별도 서버 없이 생성한 `index.html`을 읽는 로컬 정적 카탈로그다. 원본 Delta나 운영 Gold에 접속하지 않으며 기존 조회 대상을 변경하지 않는다.

## 무엇을 연결했는가

| 대상 | 확인할 내용 |
| --- | --- |
| dbt 입력 4개와 모델 24개 | 설명, 한 행의 단위와 키, 컬럼 자료형과 의미 |
| 월별 및 연간 마트 14개 | 직접 상위 입력과 하위 출력, 고정 집계 정책 |
| dbt 데이터 검사 145개 | 연결 모델, 첫 실행과 재실행 상태, 시간과 invocation ID |
| 독립 품질 규칙 17개 | 검사 조건과 책임, 실패와 경고 및 적용 제외 상태 |
| GX 검사 | 담당 규칙 DQ003부터 DQ005까지 12개 expectation의 결과 |
| 실행별 SQLite 기록 | 실행 ID, 시작과 종료, 입력 버전과 단계별 상태 및 시간 |
| 근거 파일 | 기준선, 문서, 검사 결과와 프로젝트 파일의 SHA-256 |

컬럼의 설명 출처는 dbt의 직접 설명, 기존 컬럼의 공통 설명, 미작성으로 구분한다. 동일한 컬럼 이름의 공통 설명을 쓰는 경우에도 이를 모델에 직접 선언한 문서로 표시하지 않는다. 현재 생성본의 설명 누락 컬럼은 0개다. 이는 설명의 사람이 검수한 정확도를 보증하는 값이 아니다.

`user_name`은 계정 기준이며 실제 사람 수가 아니다. 원래 MSID와 공식 녹음 MBID, 고정 곡 묶음 키는 서로 다르다. 청취 수는 보존하고 대표 순위는 고유 계정 수로 정한다. 연간 계정 수는 월별 수를 더하지 않고 사용자별 연간 기여에서 계산한다. 공식 메인과 피처링 귀속으로 아티스트별 합은 전체보다 클 수 있다. Live, Remix와 Sped Up은 구분하며 미연결 청취도 곡과 커버리지 마트에 남긴다.

## 같은 입력의 근거만 연결한다

파일 수정 시각으로 최신 결과를 임의 선택하지 않는다. dbt 실행 루트와 입력 매니페스트, 기준선 지문과 표본 행 수 및 청취 수, 모델과 매크로 정의, 문서 및 실행 invocation ID를 대조한다. 실행 로그의 프로젝트 지문과 입력 정책 및 최종 대조 결과도 일치해야 한다. 종료 기록이 없는 SQLite 로그는 완료 근거로 연결하지 않는다. 로그는 읽기 전용으로 조회하고 자동 복구하지 않는다.

독립 품질 계약은 규칙 파일의 SHA-256도 확인한다. 기존 GX 보고서는 규칙 파일 지문을 저장하지 않았으므로 기준선 및 profile의 범위 ID와 정책 버전, 규칙 ID로 연결한다. 이 차이를 카탈로그에 표시한다. 기존 GX 결과를 규칙 지문까지 검증한 이력으로 해석하지 않는다. 각 결과가 실행 당시 기록한 검증을 연결하는 것이며 원본 데이터 전체를 이번 카탈로그 생성 중 다시 검사한 것은 아니다.

dbt의 `source`와 `ref`에서 얻은 테이블 계보는 자동 연결한다. Bronze 보존, 품질 격리, 동일 청취 중복 제거와 월별 집계 및 고정 곡 정책은 별도의 문서 계보로 선언하고 고정 표 ID와 버전을 표시한다. Spark 실행의 자동 계보 수집이나 컬럼 및 행 수준 계보는 구현하지 않았다.

## 생성과 조회

입력은 완료한 dbt 표본 실행 폴더, 같은 기준선의 품질 계약 및 GX 결과, 해당 dbt 실행의 SQLite 로그다. 원천 데이터나 운영 DB의 경로를 출력 대상으로 지정하지 않는다. 이미 존재하거나 근거와 겹치는 출력 경로는 거부한다.

```bash
PYTHONPATH=src python scripts/build_data_catalog.py \
  --dbt-root data/catalog-20261024-r1/dbt \
  --quality-root data/quality-contract-20261022-r3 \
  --gx-root data/gx-quality-20261023-r2 \
  --journal data/executions/3d474c3a-2e45-4352-82fe-3a63590bc715.sqlite3 \
  --output data/catalog-20261024-r1/site-r3
```

`index.html`은 카탈로그 JSON을 포함해 단독 파일로 열 수 있다. 모델이나 컬럼, 품질 규칙을 검색하고 모델을 선택하면 관련 검사와 실행을 볼 수 있다. 기존 dbt 문서의 별도 링크는 로컬 HTTP로 제공할 때 사용한다. 필요한 경우 생성한 사이트 폴더만 `python -m http.server 8765 --bind 127.0.0.1 --directory data/catalog-20261024-r1/site-r3`로 제공한다. 원본 데이터 폴더를 HTTP에 노출하지 않는다.

출력은 `catalog.json`, `index.html`, 기존 dbt 문서 세 파일과 완료 `result.json`이다. 완료 결과에는 파일별 SHA-256과 생성 시간, 내용 파일의 저장량을 남긴다. 카탈로그 생성 자체도 별도 실행 ID로 기록한다. 원본 청취 행과 계정 값, 품질 실패 행과 traceback, 입력 Parquet와 실행 SQLite 자체는 사이트에 복사하지 않는다. SQL과 설명을 포함한 기존 dbt 문서는 로컬 조회를 위한 메타데이터다. 외부 공개 전 검토는 별도다.

## 실제 검증 범위

2026-10-24에 고정 표본 6,469행과 113,368회로 별도 dbt 실행을 만들었다. 모델 24개와 검사 145개가 첫 실행 및 재실행에서 통과했고 14개 마트는 고정 기대값, 독립 Python 계산 및 기존 SQL과 일치했다. 소스 실행 ID는 위 명령과 같으며 총 경과는 93.038초다. 이 수치는 전체 Silver의 처리 시간이 아니다.

품질 계약은 PASS 14, FAIL 0, WARN 2와 SKIP 1이다. DQ008은 월별 표본에 상세 재생 시간이 없어 검사하지 못한 상태이며 통과로 바꾸지 않는다. 경고와 적용 제외가 있어도 카탈로그의 메타데이터 생성은 완료될 수 있다. 카탈로그 완료는 데이터 승격 승인과 별개이며 `production_applied`와 `promotion_ready`는 false다.

최종 카탈로그 생성은 4.032초이며 완료 보고서 자체를 제외한 내용 파일 5개의 합은 3,864,441바이트다. 기존 dbt 실행과 품질 보고서는 재계산하지 않고 읽었다. 모든 연결 근거의 지문은 생성 전후에 같았다.

검사는 `tests/test_data_catalog.py`에서 실행한다. 다른 기준선과 행 수, 바뀐 규칙 및 모델과 매크로, 누락 결과 및 순환 계보, 다른 실행 경로와 미완료 로그를 거부한다. 실패한 검사와 경고 및 SKIP 보존, 입력 불변, HTML 삽입 방지와 재출력 차단도 확인한다. Node가 있으면 `tests/catalog_dom.cjs`로 실제 생성 HTML의 스크립트를 오프라인 DOM에서 실행해 초기 렌더링과 검색, 입력 및 모델 선택을 확인한다.

이번 환경의 브라우저 정책은 `file:` 미리보기를 허용하지 않아 실제 브라우저 화면의 시각 검수는 하지 않았다. 오프라인 JavaScript 실행 검증과 시각 검수는 다른 범위다. 정적 결과이므로 입력과 규칙이 바뀌면 다시 생성해야 한다. 운영 신선도와 연속 이력 조회, 자동 알림, OpenMetadata 및 Airflow 서버는 이번 범위에 포함하지 않는다.
