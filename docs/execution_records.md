# 실행 기록의 저장과 중단 확인

2026-10-24에 dbt 표본과 전체 생성, 소형 Silver CDF Gold 및 전체 CDF 실행과 중단 사본 복구에 실행별 기록을 연결했다. 운영 데이터, 집계 규칙과 처리 위치의 발행 조건은 바꾸지 않는다. 기존 Spark 잡의 종료 후 Delta 실행 기록은 유지하며 이번 연결 대상과 구분한다.

## 위치와 기록 범위

실행마다 UUID를 발급하고 현재 작업 디렉터리의 `data/executions/<실행 ID>.sqlite3`에 기록한다. `FLUX_EXECUTION_ROOT`로 변경할 수 있으며 로컬 쓰기 가능한 전용 경로를 사용한다. 입력 및 출력 경로와 공유하거나 운영 표 안에 두지 않는다. 출력 스냅샷 밖에 기록하므로 실행 전 검증 실패도 남고 결과 매니페스트의 파일 지문과 충돌하지 않는다. 재시도는 같은 출력 경로여도 새 실행 ID를 받는다.

| 기록 | 저장 시점과 범위 |
| --- | --- |
| 실행 ID와 작업 및 경로 | 함수 진입 전, PID와 실행 인자 포함 |
| 입력 버전 | 확인한 Silver ID와 시작 및 종료 버전, 기준선 지문 |
| 코드와 정책 지문 | 기존 보고서에서 확인한 프로젝트와 규칙 지문 |
| 단계 상태 | 단계 시작과 다음 단계 전환 또는 실행 종료 |
| 처리량 | CDF 행 수, 입력 행 수와 청취 수, 대조한 행 수 및 기간 수 |
| 시간 | UTC 시각과 실행 및 현재 단계의 경과 초 |
| dbt 호출 | 명령, 로그 위치, 시작과 반환 코드 및 측정 시간 |
| 디스크 | 대형 실행의 DiskMeter에서 5초 간격 용량과 관측 최대값 |
| 오류 | 실패 보고 또는 예외 종류와 메시지, 경계 밖 예외의 제한된 traceback |

입력 검증 전에 실패하면 확인하지 못한 버전은 채우지 않는다. 표본 실행은 기준선의 Bronze 처리 버전과 정책을, 전체 CDF는 실제 Silver 표 버전과 원본 Bronze 처리 위치를 구분한다. 새 덤프의 신선도나 누락 경고, 외부 알림, 메모리 최대값은 이번 구현에 포함하지 않는다.

기간 대조는 첫 기간, 이후 25개 기간마다, 마지막 기간에 진행 기록을 남긴다. `rows_checked`는 그 대조의 누적 행 수이고 `cdf_rows`는 변경 이미지 행 수다. 두 수를 합쳐 처리량으로 쓰지 않는다. 경과 시간은 대기와 절전 구간을 포함할 수 있으며 CPU 사용 시간이 아니다. 종료 전 경과 시간은 마지막으로 저장한 이벤트까지의 관측값이다.

## 저장과 상태 판정

Python 표준 라이브러리 SQLite에 이벤트를 추가하고 매번 독립 트랜잭션으로 커밋한다. 동기 저장 설정은 `FULL`이다. 백그라운드 디스크 측정도 같은 기록기를 사용하고 스레드 잠금으로 쓰기를 직렬화한다. 최대값은 각 측정과 함께 저장한다. 샘플 사이의 순간 최대값은 알 수 없다. 저장 설정의 의미는 [SQLite의 동기 설정](https://www.sqlite.org/pragma.html#pragma_synchronous), 미완료 쓰기의 복구 원리는 [원자적 커밋 설명](https://www.sqlite.org/atomiccommit.html)을 따른다.

`succeeded`는 실행 함수가 `completed: true`를 반환한 경우다. `failed`는 실패 보고, 예외 또는 비정상 종료 요청이고 `interrupted`는 처리할 수 있었던 KeyboardInterrupt다. 프로세스 강제 종료는 종료 이벤트를 남길 수 없으므로 `unfinished`로 표시한다. 이는 현재 살아 있다는 뜻도, 실패가 확정됐다는 뜻도 아니다. 마지막 단계와 시각을 보고 실제 프로세스와 기존 결과를 확인한다. 다음 단계로 전환되면 이전 단계를 성공으로 닫고, 그 전에 종료되면 완료를 추측하지 않는다.

로그를 처음 만들지 못하면 작업을 시작하지 않는다. 이후 로그 쓰기 실패도 실행에 전달하며 디스크 측정 스레드의 쓰기 실패는 종료 정리에서 확인한다. 원래 예외를 처리하다 종료 기록까지 실패하면 원래 예외를 유지하고 기록 실패를 표준 오류로 알린다. 기록 실패가 이미 커밋된 결과를 취소한다는 뜻은 아니다. 조회 대상과 처리 위치는 기존 완료 매니페스트, 지문과 검증 절차로 판단하며 실행 기록을 승인 근거로 대신 쓰지 않는다.

SQLite 쓰기 도중 강제 종료되면 미완료 쓰기의 rollback journal이 남을 수 있다. 조회 도구는 실행 기록 DB를 `mode=rw`로 열어 SQLite가 미완료 쓰기를 되돌리게 한다. 새 DB를 생성하지 않으며 입력이나 결과 데이터 파일을 열지 않는다. 기록 디렉터리의 쓰기 권한이 필요하고 이미 커밋된 이벤트는 보존된다. 검증은 프로세스 종료와 트랜잭션 복구 범위이며 물리 디스크 손상이나 전원 차단 실험은 아니다. 자동 데이터 복구 기능도 포함하지 않는다.

## 확인 명령

기존 실행 명령은 그대로 사용한다. 기록 경로를 바꾸려면 실행 전에 지정한다. 아래는 Git Bash 예시다.

```bash
export FLUX_EXECUTION_ROOT="$(pwd)/data/executions"
python scripts/inspect_execution.py data/executions/<실행-ID>.sqlite3
python scripts/inspect_execution.py data/executions/<실행-ID>.sqlite3 --events
```

첫 조회는 상태와 마지막 단계, 입력과 측정값을 보여 준다. `--events`는 시점별 이력도 보여 준다. 실행 인자와 오류에 로컬 경로가 포함될 수 있어 원본 기록은 로컬에 보관한다. 자동 삭제와 압축 정책은 이번에 추가하지 않았다.

## 검증과 후속

다음 단위였던 [작은 Delta 사본의 독립 백업 복원](backup_restore.md)을 2026-10-24에 별도로 검증했다. 아래 실행 기록 기능의 검증 범위와 복원 범위를 구분하며 대형 백업 및 운영 보존 정책은 남아 있다.

`tests/test_execution.py`는 상태 전환, 검증 전 실패, 재시도 ID 분리, 하위 결과와 상위 상태의 분리, 디스크 표본과 기록 오류, SQL 대조 진행량 및 조회 명령을 검증한다. 실제 자식 프로세스를 종료하는 두 검사는 완료 이벤트 없이 직전 기록이 남는지와 SQLite 쓰기 중 미완료 이벤트만 롤백되는지를 확인한다. 후자는 처음 읽기 전용 조회에서 실패한 뒤 수정했다.

`tests/test_dbt_runtime.py`는 작은 고정 입력의 실제 dbt 생성과 14개 마트 대조에서 기록을 검증한다. 전체 운영 Silver 재계산은 이번 변경을 위해 반복하지 않는다. 독립 백업 복원, 기록 보존 정책, 전체 입력의 비용 개선과 실제 새 덤프 운영은 다음 단계다.

2026-10-24 로컬 검증은 새 실행 기록 검사 19개가 1.70초, 기본 전체가 1,040 passed와 21 skipped 및 12 deselected로 119.25초였다. 실제 dbt 검사는 1개가 244.61초에 통과했다. 이 검사는 모델 24개 및 검사 145개를 두 차례 실행하고 14개 마트 대조와 오류 주입 17종을 확인한다. 기록에 고정 입력 버전 0, 단계 다섯 개의 완료와 청취 27회 및 14개 대조 완료가 남았다. 로컬에만 있는 기존 조사 초안이 있어 깨끗한 CI의 검사 수와는 구분한다.

[원격 CI 실행](https://github.com/prgmd/flux/actions/runs/40072185690)에서도 기본 1,036 passed와 22 skipped 및 12 deselected가 19.64초에, 실제 dbt 7개가 325.56초에, GX 11개가 11.85초에 통과했다. 운영 데이터나 대규모 원본을 CI에 올리지 않았다.
