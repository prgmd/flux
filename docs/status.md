# 현재 상태와 남은 작업

2026-10-19 문서 점검 기준. 초기 명세의 단계 완료와 최신 입력 및 모델의 완료를 구분한다. 데이터 생성 수치는 [재생성 검증](rebuild_30seconds.md), 곡 식별 조사 조건은 [집계 정책](user_recording_counts.md)을 따른다.

## 완료 범위

| 대상 | 확인한 상태 | 아직 포함하지 않은 범위 |
| --- | --- | --- |
| 통합 Bronze | 기존 입력과 추가 두 덤프, 162,679,797행 | 다음 덤프 수집과 실제 대규모 월별 증분 |
| 30초 정제 | 품질 격리 후 사용자+MSID+청취 시각 중복 제거, 상세 157,351,363행, 격리 1,318,299행 | 다른 MSID 사이의 동일 사건 중복 제거 |
| 월별 Silver | 사용자 이름+MSID+UTC 청취 월 80,563,985행, play_count 합 157,351,363회, 전수 대조 완료 | 최종 곡 식별자와 아티스트 귀속 확정 |
| 저장량 축소 | 사전과 격리 포함 활성 파일 5,148,699,591바이트, 이전 조합 대비 66.9% 감소 | 보관 중인 이전 상세와 Bronze의 디스크 공간 삭제 |
| 월별 증분 구현 | 소형 변경과 복구 테스트, 실제 같은 입력 재실행의 무변경 확인 | 다음 대규모 덤프와 7일 연속 대조, 성능 목표 검증 |
| 기존 Gold | 이전 상세 모델과 입력 범위의 일별 및 주별 마트 생성과 검증 | 최신 통합 입력의 월별 Gold, 현재 보류 |
| 곡 식별 조사 | MBID와 이름 가정의 전체 계산, 실제 곡 표본의 별도 집합 계산 | 후보의 사실 정확성 검수와 연결 승인 |

MSID별 월간 횟수의 계산 정확성과 같은 녹음의 식별 정확성은 별개다. 월별 표의 전수 대조가 끝났어도 최종 곡별 지표의 정제가 끝난 것은 아니다. 운영 경로 승격도 별도다.

이름 기준 조사는 기존 호스트 프로세스의 생존을 확인한 뒤 최종 완료와 원본 불변까지 확인했다. 제한된 프로세스 목록만 보고 종료됐다고 판단했던 기록을 정정했다. [실제 이름 후보 사례](measurements/2026-10-19-name-candidates.md)에는 앨범 표기 차이, 녹음 버전 차이와 오연결 후보를 구분했다.

이후 전체 메타데이터 사전에서 제목 변형 후보 사례집을 생성했다. 접미사 경로 760,451묶음과 같은 MBID의 다른 제목 83,222묶음을 보관하며 확정 동일 곡 수로 해석하지 않는다. GOLDEN [Explicit]과 (Ver. A)는 특정 두 MSID 쌍의 연결 근거를 검수했다. [규칙 후보와 사례집 범위](recording_link_rules.md)에 근거와 자동 연결 제외 유형을 기록했다. 실제 매핑 적용은 아직 하지 않았다.

공식 녹음 크레딧의 전체 대조도 별도 사본에서 완료했다. 승인한 문자 정리 규칙을 조사본에 적용한 일치 후보는 21,304,420회(전체의 약 13.54%)이며 최종 연결 완료 수치가 아니다. 미연결과 충돌을 보존하고 문자 차이, 별칭, 옛 ID를 추가 검수한다. 테스트와 상태별 수치는 [전체 점검 결과](review_20261019.md)를 따른다. 최신 월별 Gold는 이 정제 이후 구축한다.

## 다음 순서와 완료 조건

1. **조사 결과와 사례 분류를 마무리한다.** MBID가 같은 MSID부터 청취자 수가 많은 후보를 검토한다. 이름 기준 전체 계산은 완료했다. 다음은 결과의 실제 연결 근거를 검수한다. 제한된 프로세스 조회만으로 종료를 판단하지 않는다. AI는 표기 차이, 앨범 차이, 버전 차이와 잘못된 연결을 분류하고 사람이 승인한다. `[Explicit]` 같은 표지는 후보로 조사하되 일괄 삭제 규칙으로 확정하지 않는다.
2. **곡 연결과 동일 사건 제거를 각각 결정한다.** 원본 MSID를 유지하고 별도 곡 묶음 키, 연결 근거와 규칙 버전을 둔다. 곡 연결만으로 총 횟수는 줄지 않는다. 같은 사용자+연결된 녹음+동일 시각의 초과 기록을 제외하는 규칙은 별도 검수한다. 월별 표에는 시각과 앨범명이 없으므로 보존한 상세나 Bronze에서 확인한다. 승인된 후보만 별도 경로에서 보정하고 키별 차이를 대조한다.
3. **곡별 아티스트 귀속을 정한다.** 공식 녹음 크레딧의 메인과 피처링을 포함하고 제작진 관계만 있는 인물은 제외한다. 사람을 전역 제외하지 않는다. MBID 미연결, 버전 충돌과 자료 미확인 곡은 별도 상태와 커버리지로 남긴다. 귀속 오류만 고치면 Silver의 play_count는 유지하고 아티스트 집계를 다시 계산한다.
4. **검수한 월별 Silver로 Gold를 만든다.** 월별 곡과 월별 아티스트부터 만든 뒤 아티스트 내 곡과 아티스트 전체를 연간으로 확장한다. 청취 수는 보존하고 순위는 고유 청취자 수, 동률은 같은 순위, 표시는 이름순으로 정한다. 아티스트 내 곡 비중, 최대 계정 비중과 연결 커버리지를 포함한다. 기간은 도착 월이 아닌 UTC 청취 월이며 늦게 도착한 기록은 과거 월을 바꾼다. 연간 청취자 수는 월별 수의 합이 아닌 기간 전체의 고유 계정 수로 검증한다.
5. **증분 운영을 검증한다.** 새 덤프 투입 전에 통합 Bronze의 CDF를 켜고 필요한 이력을 보존한다. 월별 증분 결과를 같은 고정 원본 버전의 전체 계산과 대조한다. 같은 덤프 재실행, 다른 덤프, 수정과 삭제, 중단 복구를 검증한다. 곡 연결 규칙을 바꿨을 때 과거 월의 재계산 범위도 정한다. 7일 연속 대조와 처리 시간 목표는 별도로 측정한다.

1-3번이 Gold의 선행 조건이다. 5번의 CDF 준비는 실제 다음 덤프 투입의 선행 조건이며 지금 문서 점검에서 설정을 변경한 것은 아니다. 청취자별 분석은 월별 사용자 키로 가능하지만 공개 범위와 지표는 아직 정하지 않았다.

## 후속 확장과 해석 한계

PostgreSQL 서빙 적재, FastAPI 조회와 Airflow 파이프라인 DAG 통합은 후속 확장이다. 현재 Airflow는 스모크 DAG이며 Kafka와 실시간 수집은 초기 배치 범위에 포함하지 않는다. 현재 자료로도 배치 메달리온 구현 경험은 설명할 수 있으나 최신 월별 모델의 Gold 완료로 표현하지 않는다.

청취자 수는 계정 수다. 한 사람이 여러 계정을 쓰는 경우를 구분할 수 없으며 ListenBrainz 표본을 전체 인구의 팬덤 또는 대중성으로 단정하지 않는다. 공동 참여 아티스트에게 각각 횟수를 부여하므로 아티스트별 횟수 합은 전체 청취 수와 같지 않을 수 있다. 순위와 집중도는 최종 귀속 규칙 적용 후 다시 비교한다.
