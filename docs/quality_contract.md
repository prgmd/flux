# 고정 표본의 품질 계약

## 범위와 상태

품질 규칙의 정본은 [quality_rules.json](../src/flux/validation/quality_rules.json)의 `quality-contract-v1`이다. P0에서 고정한 월별 Silver 입력과 기존 정책의 14개 표본 Gold 마트를 검사한다. 규칙마다 식별자, 심각도, 단계, 대상, 담당, 적용 범위, NULL 허용 여부와 선행 검사를 기록한다. 현재 실행 담당은 `flux.validation`이다.

`PASS`는 검사한 범위의 조건 만족, `FAIL`은 오류, `WARN`은 조사할 경고다. `SKIP`은 입력이 없거나 선행 검사가 실패해 판정하지 못했다는 뜻이다. 검사 완료 여부인 `evaluation_completed`와 오류 유무인 `quality_passed`를 구분한다. 오류가 하나라도 있으면 명령은 종료 코드 1을 반환한다. 경고만 있으면 0을 반환하되 경고를 보고서에 남긴다. 표본 통과는 전체 데이터 검증이나 운영 승격의 근거가 아니므로 `promotion_ready`는 항상 false다.

## 실패 규칙

| ID | 단계와 대상 | 실패 조건과 허용 범위 |
| --- | --- | --- |
| DQ001 | 입력 자료 | P0 완료 자료를 읽지 못하거나 파일 지문이 다름. 검사 전후 지문을 확인함 |
| DQ002 | 실행 문맥 | 계정 키가 user_name이 아님, UTC가 아님, 30,000ms 정책이 아님, 표본 범위가 비어 있거나 Bronze 및 Silver 처리 위치가 불일치함 |
| DQ003 | 월별 키 | 빈 입력, 빈 사용자 이름이나 MSID, 실제 달력에 없는 YYYY-MM |
| DQ004 | 월별 단위 | 사용자 이름+MSID+UTC 청취 월 키 중복 |
| DQ005 | 횟수 | play_count가 양의 정수가 아님. NULL, 0, 음수, 소수와 bool은 실패 |
| DQ006 | 사전과 참조 | 빈 사전 키, 중복 MSID나 곡 키, 중복 곡+아티스트 크레딧, 누락된 참조. recording MBID 누락은 허용 |
| DQ008 | 정상으로 선언한 상세 | 기존 quality.judge가 거절하는 행이 포함됨. 재생 시간 없는 행은 허용. 상세 입력이 없으면 SKIP |
| DQ009 | 격리 표본 | 재판정에서 통과하거나 저장된 최초 거절 사유와 다름 |
| DQ010 | 횟수 보존 | 월간과 연간 각각 곡, 커버리지, 버전, 계정, 식별 상태의 횟수 합이 입력과 다름 |
| DQ011 | 지표 범위 | 음수나 비정수 횟수, 청취자 수가 청취 수보다 큼, 최대 계정 횟수가 전체보다 큼, 비중이 0-1 범위 밖이거나 비유한 수. 집중도는 0 초과, 유효 청취자 수는 1 이상 실제 계정 수 이하 |
| DQ012 | 독립 기대값 | 14개 마트의 키, 열, 값이 Python 재계산과 다름. 실수는 상대 및 절대 허용 오차 1e-12 |
| DQ013 | 버전 구분 | 사전의 버전과 곡 라벨이 다름. 여러 버전 라벨이 섞인 곡은 conflicting_labels로 명시해야 함 |
| DQ014 | 검수 범위 | P0 참조 전용 R9 자료에 승인 수 또는 매핑이 생김. 이 버전은 승인 0과 빈 매핑만 허용 |

공동 참여 아티스트에게 각각 청취 수를 부여하므로 아티스트 전체 합을 입력 총합과 같게 강제하지 않는다. 아티스트별 값은 DQ012의 독립 기대값으로 검사한다. 청취자 수 순위와 동률 처리를 대조하고, 연간 청취자 수는 월별 수의 합이 아닌 연간 고유 계정으로 재계산한다. 전체 Gold의 순위는 별도 참조이며 작은 표본의 순위와 직접 비교하지 않는다.

DQ013은 고정된 분류의 보존 검사다. 공식 버전 판정 자체의 사실 정확성을 새로 증명하지 않는다. Live, Remix와 Sped Up을 지우거나 unmarked를 원곡으로 간주하지 않는다. DQ014도 향후 승인 검증의 대체물이 아니다. 사람이 승인한 비어 있지 않은 매핑을 허용하려면 검수 저널과 관측 근거 및 최신 상태를 재검증하는 별도 계약이 필요하다.

## 경고와 정보 규칙

| ID | 수준 | 조건 |
| --- | --- | --- |
| DQ007 | 정보 | 메타데이터 변형 행의 recording MBID 누락 수를 기록하고 허용함. 청취 사건 수의 누락률과 구분 |
| DQ015 | 경고 | 원문 표본의 ms_played가 비숫자, bool 또는 비유한 값이면 경고. 없는 값은 별도로 세고 허용 |
| DQ016 | 경고 | 보관 덤프의 시간 구간이 누락 또는 겹침, 다음 연속 입력이 미확정 |
| DQ017 | 경고 | 통계 비교 기준이 없거나 범위가 다름, 같은 범위의 지표가 변함 |

DQ015는 정제 동작을 바꾸지 않는다. 숫자로 해석되는 30,000 미만은 기존 품질 판정이 격리하며, 문자열 `"30000"`과 `"30001"`은 통과한다. 해석할 수 없는 값은 기존 정책대로 유지하되 경고로 관측한다. 월별 입력에는 개별 재생 시간이 없으므로 상세 품질 통과를 추정하지 않는다. Bronze 원문 표본도 정상 상세로 선언한 입력이 아니다.

DQ017은 목적을 두고 고른 한 표본에서 운영 경고 임계값을 만들지 않는다. 월별 행 수, 총 횟수, 메타데이터 MBID 누락률, 연결된 청취 비중과 원문 표본 거절률을 기록한다. 표본 ID, 계정 키, 시간 기준과 정책 버전이 같은 기준 자료만 수치 대조한다. 동일 표본 재실행의 완전 일치는 재현성 확인이며 시간에 따른 정상 변동의 검증이 아니다. 실제 경고 임계값은 비교 가능한 여러 입력의 분포를 측정한 뒤 정한다.

## 실행과 산출물

Git Bash에서 호스트 가상환경과 저장소의 src를 사용한다. Spark나 운영 원본 경로를 열지 않는다. 출력은 고정 입력과 분리된 새 폴더만 허용한다.

```bash
PYTHONPATH=src venv/Scripts/python scripts/check_quality_contract.py \
  --baseline data/governance-baseline-20261022-r2 \
  --output data/quality-contract-new-run

PYTHONPATH=src venv/Scripts/python scripts/drill_quality_contract.py \
  --baseline data/governance-baseline-20261022-r2 \
  --output data/quality-drill-new-run
```

품질 검사는 result.json에 규칙별 판정과 관측 요약, 정책 및 입력 지문을, profile.json에 통계 비교 자료를 저장한다. 원문과 사용자 이름은 새 보고서에 기록하지 않는다. 이전 profile.json을 `--reference-profile`로 주면 같은 범위인지부터 검사한다. 실패 주입은 매번 메모리 사본을 만들며 기존 Parquet를 수정하지 않는다. 실험 자체의 기대 판정이 어긋나면 종료 코드 1이다. [실제 실행 결과](measurements/2026-10-22-quality-contract.md)를 따른다.

## 이후 도구 연결

P1은 계약과 독립 실행기를 준비한 단계였다. 이후 P3에서 모델 키와 참조, 횟수 및 보존을 dbt로 검증했고 P4에서는 [GX 고정 표본](gx_quality.md)의 실제 검사와 보고 및 sandbox 결과 전환 차단을 연결했다. DQ003-DQ005는 GX, 상세 품질은 기존 Spark 및 Python, 모델 계약은 dbt가 담당하며 입력과 검수 및 프로파일의 별도 책임을 유지한다. 실제 운영 승격 차단의 전체 연결과 대규모 엔진 및 통계 보정은 후속이다. 하나의 규칙이 여러 도구에 복제되면 담당과 실행 위치를 명시하고 같은 실패 주입으로 일치 여부를 확인한다. P0 자료 무결성과 검수 범위 검사는 Flux가 계속 담당한다.
