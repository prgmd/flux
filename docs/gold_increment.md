# Gold 증분의 영향 기간과 검증 범위

## 현재 P5 진행 상태

영향 기간 계산에 이어 고정 사본에서 dbt 14개 마트의 실제 기간 교체를 검증했다. 재실행, 마지막 키 및 연도 삭제, 메타데이터와 정책 변경, SQL 실패와 실제 프로세스 종료 후 복구를 확인했다. 이후 [실제 Silver CDF 연결](silver_cdf_gold.md)도 소형 실험본에서 검증했다. 이후 [전체 Silver 통제 변경](measurements/2026-10-23-full-silver-cdf-gold.md)의 14개 전수 대조와 시간 및 저장량도 확인했다. 아래 사본 계산 규칙은 그 연결의 하위 구성 요소로 유지하며 새 덤프 전체와 대량 변경 및 운영 승격은 후속이다. 운영 원본과 Gold는 유지했다. [실측과 테스트](measurements/2026-10-23-dbt-period-increment.md)를 따른다.

## 영향 범위

횟수 변경, 새 키와 삭제는 변경 전후 청취 월을 모두 포함한다. 계정이나 MSID 및 월이 바뀌면 기존 월과 새 월을 다시 계산하고 해당 연도를 포함한다. 마지막 행 삭제로 사라진 기간도 반환하므로 결과가 없는 새 기간을 무시하고 옛 행을 남기는 일이 없도록 한다. 같은 입력은 빈 영향 목록이다.

곡 연결과 라벨이 바뀌면 같은 곡 키의 다른 MSID가 등장한 기간까지 포함한다. 크레딧의 추가와 삭제 또는 이름 변경은 해당 아티스트의 다른 곡이 등장한 기간도 보수적으로 포함한다. 현재 아티스트 대표 이름은 크레딧 전체의 최솟값으로 정하므로 한 곡의 이름 근거가 다른 달의 표시값도 바꿀 수 있기 때문이다. 같은 기간의 순위는 대상 아티스트 한 행만 고치지 않고 전체를 다시 구해야 한다.

정책 지문이 없거나 바뀌면 모든 관측 기간을 반환하고 `requires_full_rebuild`를 참으로 표시한다. 범위를 확인할 수 없는 정책 변경을 적은 행의 변경으로 간주하지 않는다. 입력의 중복 키, 잘못된 월과 횟수 및 사전 참조 누락은 거부한다.

## CDF 입력 경계

`cdf_periods()`는 source_id와 이전 표 ID, 이전 및 종료 버전과 범위 완전성 확인을 요구한다. insert와 delete, update_preimage와 update_postimage의 월을 모두 포함한다. 버전 범위 밖의 행과 알 수 없는 변경 유형, 짝이 빠진 갱신과 원본 교체 및 불완전 범위는 거부한다. 새 버전이 없는 재실행은 빈 기간이다.

이 함수는 전달받은 CDF 행의 검증과 기간 계산을 담당한다. 실제 Delta 파일 읽기와 완전성의 증명, 운영 체크포인트 갱신까지 구현한 것은 아니다. 다음 통합 단계에서 고정한 Silver 버전과 실제 변경 피드를 연결하고 스냅샷 차이 및 전체 재계산에 대조한다.

## 고정 실제 표본의 제어 변경

`data/gold-impact-20261023/result.json`의 입력은 P0 6,469행과 113,368회다. 실제 새 Silver 버전이 아니라 메모리 사본에서 한 가지 변경씩 넣은 실험이다. 출력에는 계정명을 넣지 않았다.

| 제어 변경 | 영향 월 수 |
| --- | ---: |
| 같은 입력 | 0 |
| 한 행의 횟수 +1 | 1 |
| 한 행의 월 이동 | 2 |
| 한 달의 마지막 기여까지 삭제 | 1 |
| 첫 곡 라벨 변경 | 19 |
| 첫 크레딧의 아티스트 이름 변경 | 221 |
| 정책 지문 변경 | 255 |

아티스트 이름 변경의 221개월은 전체 데이터에 대한 비율이 아니라 이 목적 표본의 범위다. 기존 기준 자료의 지문은 같았다. 순수 영향 규칙 18개 및 기존 결과 전환과 입력 가드를 합친 관련 검사 31개를 통과했다. 이 숫자를 실제 Gold 증분 생성의 통과 수치로 사용하지 않는다.

## 다음 단위

실제 Silver CDF 범위의 읽기와 처리 위치 연결은 소형 사본에서 검증했다. [소형 실측](measurements/2026-10-23-silver-cdf-gold.md)의 복구 근거를 유지하고 [전체 규모 실행](full_gold_cdf.md)은 별도의 SQL 및 Delta 경로로 검증했다. 작은 Python 프로토타입의 행 수 제한은 유지한다. 이후 새 덤프 전체와 대량 CDF, 버전 고정 승인 매핑 입력 및 운영 복구를 확장한다.


## dbt 기간 교체의 동작

기본값은 기존 table 전체 생성이다. flux_incremental=true와 flux_months 및 flux_years를 명시했을 때만 최종 14개 모델을 incremental append로 실행한다. 각 모델의 pre_hook가 영향 기간의 기존 행을 모두 지우고 해당 기간 전체의 새 결과를 넣는다. 새 결과가 비어도 삭제는 수행하므로 마지막 행이 사라진 기간에 옛 키가 남지 않는다. 숫자에 변경량만 더하는 방식으로 고유 계정과 순위를 갱신하지 않는다.

입력과 중간 사용자 기여에는 전체 기간을 유지하고 최종 마트의 교체 범위에 기간 조건을 적용한다. 따라서 연간 고유 계정과 최대 기여 및 집중도는 그 연도의 모든 월에서 다시 계산한다. 월별 최종 지표를 합치지 않는다. bool 설정과 월 및 연도 목록을 컴파일 시 검사하며 잘못된 날짜나 누락된 목록을 SQL로 실행하지 않는다.

여러 dbt 모델의 갱신은 하나의 트랜잭션이 아니다. 완료된 이전 DB를 새 경로로 복사하고 그 사본에서만 입력과 모델을 갱신한다. 모델 및 데이터 테스트의 전체 노드 집합과 성공 상태, Python 독립 전체 계산 및 기존 SQL 전체 계산으로 14개 결과를 대조하고 영향 밖의 모든 행도 비교한 뒤 완료를 표시한다. 모델이나 정책 지문이 바뀌면 명시적인 전체 재생성이 필요하다. 원본과 복사 프로젝트 및 입력 지문이 유지되는지도 검사한다.

## 입력과 재시작

이 실행기는 월별 입력 최대 10,000행의 제어 프로토타입이다. 다음 입력 JSON은 monthly, dimension, labels 및 credits의 네 배열이며 현재 원본과 같은 열 구조를 요구한다. 수식은 그대로 두고 메타데이터나 횟수를 제어 변경해 검증하는 용도다. 실제 Delta 변경 버전을 수신하거나 체크포인트를 진전시키는 명령이 아니다.

입력은 스키마를 지정한 JSON 파일을 DuckDB가 한 번에 읽어 적재한다. 행별 Python 삽입은 실제 표본에서 수분 동안 입력 단계에 머물러 미완료 사본을 보존하고 중단했다. 새 경로의 파일 적재로 확인했다. 이전 DB와 입력 및 현재 프로젝트는 수정하지 않는다. 자신의 결과에는 이전 스냅샷 경로와 결과 및 DB 지문, 새 입력과 실행 프로젝트의 지문을 남긴다.

```bash
PYTHONPATH=src data/dbt-runtime/Scripts/python scripts/update_dbt_gold.py \
  --previous data/dbt-yearly-20261023 \
  --next-snapshot data/controlled-next-snapshot.json \
  --output data/dbt-period-new
```

같은 입력이면 dbt를 다시 실행하지 않고 전체 대조와 파일 지문을 확인한다. 실패한 디렉터리는 다음 입력의 기준으로 사용할 수 없다. SQL 실패나 --crash-after-build 실험의 종료 코드 86 뒤에는 마지막 completed=true 사본을 --previous로 지정하고 같은 다음 입력을 새 출력 경로에서 재실행한다. 운영 조회 대상 교체 옵션은 없다.

```bash
PYTHONPATH=src data/dbt-runtime/Scripts/python scripts/drills/dbt_period_metadata.py \
  --previous data/dbt-period-delete-20261023-r2 \
  --output data/dbt-period-metadata-new
```

위 드릴은 라벨과 크레딧 이름을 제어 변경하고 정책 태그 변경의 전체 재생성 전환을 검증한다. 실제 음악 사실의 보정이나 승인 매핑 적용으로 해석하지 않는다. 기본 로직은 pytest 기본 실행, 실제 dbt와 강제 종료 및 컴파일 검사는 -m dbt로 분리한다.
