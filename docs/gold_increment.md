# Gold 증분의 영향 기간과 검증 범위

## 현재 P5 진행 상태

첫 단위는 다시 계산할 기간을 빠뜨리지 않는 순수 로직이다. `gold_changes.affected_periods()`는 고정한 변경 전후 월별 기여와 곡 사전, 라벨 및 크레딧을 비교한다. P0 표본의 제어 변경 실험까지 확인했으며 dbt의 실제 기간 교체와 새로운 대규모 Silver CDF 연결은 아직 구현 완료로 표시하지 않는다. 운영 원본과 Gold는 유지했다.

## 영향 범위

횟수 변경, 새 키와 삭제는 변경 전후 청취 월을 모두 포함한다. 계정이나 MSID 및 월이 바뀌면 기존 월과 새 월을 다시 계산하고 해당 연도를 포함한다. 마지막 행 삭제로 사라진 기간도 반환하므로 결과가 없는 새 기간을 무시하고 옛 행을 남기는 일이 없도록 한다. 같은 입력은 빈 영향 목록이다.

곡 연결과 라벨이 바뀌면 같은 곡 키의 다른 MSID가 등장한 기간까지 포함한다. 크레딧의 추가와 삭제 또는 이름 변경은 해당 아티스트의 다른 곡이 등장한 기간도 보수적으로 포함한다. 현재 아티스트 대표 이름은 크레딧 전체의 최솟값으로 정하므로 한 곡의 이름 근거가 다른 달의 표시값도 바꿀 수 있기 때문이다. 같은 기간의 순위는 대상 아티스트 한 행만 고치지 않고 전체를 다시 구해야 한다.

정책 지문이 없거나 바뀌면 모든 관측 기간을 반환하고 `requires_full_rebuild`를 참으로 표시한다. 범위를 확인할 수 없는 정책 변경을 적은 행의 변경으로 간주하지 않는다. 입력의 중복 키, 잘못된 월과 횟수 및 사전 참조 누락은 거부한다.

## CDF 입력 경계

`cdf_periods()`는 source_id와 이전 표 ID, 이전 및 종료 버전과 범위 완전성 확인을 요구한다. insert와 delete, update_preimage와 update_postimage의 월을 모두 포함한다. 버전 범위 밖의 행과 알 수 없는 변경 유형, 짝이 빠진 갱신과 원본 교체 및 불완전 범위는 거부한다. 새 버전이 없는 재실행은 빈 기간이다.

이 함수는 전달받은 CDF 행의 검증과 기간 계산을 담당한다. 실제 Delta 파일 읽기와 완전성의 증명, 운영 체크포인트 갱신까지 구현한 것은 아니다. 다음 통합 단계에서 고정한 Silver 버전과 실제 변경 피드를 연결하고 스냅샷 차이 및 전체 재계산에 대조한다.

## 고정 실제 표본의 제어 변경

`data/gold-impact-20261023/result.json`의 입력은 P0 6,469행과 113,368회다. 실제 새 Silver 버전이 아니라 메모리 사본에서 한 가지 변경씩 넣은 실험이다. 출력에는 계정명을 넣지 않았다.

| 제어 변경 | 영향 월 수 |
| --- | ---: |
| 같은 입력 | 0 |
| 한 행의 횟수 +1 | 1 |
| 한 행의 월 이동 | 2 |
| 한 달의 마지막 기여까지 삭제 | 1 |
| 첫 곡 라벨 변경 | 19 |
| 첫 크레딧의 아티스트 이름 변경 | 221 |
| 정책 지문 변경 | 255 |

아티스트 이름 변경의 221개월은 전체 데이터에 대한 비율이 아니라 이 목적 표본의 범위다. 기존 기준 자료의 지문은 같았다. 순수 영향 규칙 18개 및 기존 결과 전환과 입력 가드를 합친 관련 검사 31개를 통과했다. 이 숫자를 실제 Gold 증분 생성의 통과 수치로 사용하지 않는다.

## 다음 단위

dbt 모델의 기존 기본 동작은 전체 재생성으로 유지한다. 명시적으로 영향 기간을 전달한 사본 실행에서만 기간 전체를 교체하고, 없어진 키까지 삭제하는 경로를 추가한다. 연간 고유 계정과 최대 기여 및 집중도는 해당 연도의 사용자별 기여에서 재계산한다. 재실행과 다음 변경, 과거 도착, 매핑 및 정책 변경과 중단 복구를 기존 전체 결과에 대조한 뒤 P5의 실제 실행 완료를 판단한다.
