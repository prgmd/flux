# 검증과 실행 근거

입력 Delta 버전과 규칙을 고정하고, 새 경로에서 만든 결과를 기존 결과 및 독립 계산과 대조합니다. 완료 표시와 품질 검사를 통과한 결과만 사용하며, 아래 검증에서 운영 데이터의 조회 경로는 교체하지 않았습니다.

| 검증 | 확인한 범위와 결과 |
| --- | --- |
| [dbt 전체 대조](dbt_full.md) | 월별 Silver 80,563,985행에서 24개 모델과 데이터 검사 145개를 실행했습니다. Gold 14개가 기존 결과의 모든 키와 값 대조를 통과했고 최종 Parquet의 SHA-256도 일치했습니다. |
| [품질 계약](quality_contract.md)과 [GX](gx_quality.md) | 고정 표본 6,469행, 113,368회에서 계약 17개 규칙을 검사해 실패 0, 경고 2, 적용 제외 1을 기록했습니다. GX는 이 중 3개 규칙의 12개 검사를 담당하며, 불량과 변조 결과의 전환 차단도 검증했습니다. |
| [Silver CDF와 Gold 연결](silver_cdf_gold.md) | 수정과 삭제를 포함한 변경에서 영향을 받는 월과 연도를 다시 계산합니다. 작은 사본에서 재실행과 두 중단 지점의 프로세스 종료 복구를 전체 계산과 대조했습니다. |
| [전체 규모 CDF 대조](measurements/2026-10-23-full-silver-cdf-gold.md) | 전체 Silver 사본에 통제한 변경 이미지 6행을 적용했습니다. Gold 14개와 영향 밖 기간이 동일 종료 버전의 전체 재계산과 일치했습니다. 대량 변경 처리율 실험과는 구분합니다. |
| [실행 기록](execution_records.md)과 [복원](backup_restore.md) | 입력 버전, 단계별 상태, 처리량, 시간과 오류를 SQLite에 남깁니다. 작은 표본의 Delta 4개 표와 이력, 처리 위치, 규칙 파일을 새 경로에 복원해 256개 월별 키와 258회의 일치를 확인했습니다. |

[로컬 데이터 카탈로그](data_catalog.md)는 dbt 모델의 의미와 계보에 품질 결과와 실행 이력을 연결합니다. 입력과 모델 정의 및 실행 ID가 같은 범위의 근거만 연결하고, 경고와 적용 제외도 그대로 표시합니다. Bronze에서 Silver까지는 선언한 외부 계보, dbt 내부는 모델 의존 관계로 구분합니다.

[GitHub Actions](../.github/workflows/data-contracts.yml)에서는 기본 로직, 실제 dbt와 실제 GX 검증을 분리해 실행합니다. Spark와 전체 데이터 대조는 별도 실행으로 유지합니다. [자동 검증 범위](ci.md)에서 재현 방법을 확인할 수 있습니다.
