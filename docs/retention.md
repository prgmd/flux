# Delta 보존 정책

Delta는 덮어쓸 때 옛 파일을 지우지 않는다. 로그에 "이제부터 새 것을 본다"고 적을 뿐이다.
그래서 과거로 돌아갈 수 있고, 그만큼 디스크를 더 쓴다.
`VACUUM`은 그 옛 파일을 지운다. 지운 만큼 과거로 갈 수 없어진다.

**얼마나 오래 되돌릴 수 있게 둘 것인가**가 정해야 할 값이다.

## 실측 (2026-09-07)

31일치를 적재한 Bronze의 상태다. 근거는 `measurements/2026-09-07-bronze-30days.md`.

| 항목 | 값 |
| --- | --- |
| 활성 데이터 | 24.76GB |
| 디스크 점유 | 27.09GB |
| 회수 가능 | 2.33GB (9%) |
| Delta 버전 | 35개 |
| 하루당 활성 | 0.80GB |

회수 가능한 2.33GB는 재적재가 남긴 것이다. 평상시 적재는 새 구획을 더할 뿐이라
옛 파일을 만들지 않는다. 옛 파일은 **같은 덤프를 다시 적재할 때** 생기고,
그 양은 그 덤프 하루치인 약 0.80GB다.

## 결정

**Bronze는 기본값 7일(168시간)을 쓴다.**

근거는 셋이다.

1. **비용이 작다.** 최악의 경우가 7일 연속 재적재이고 그래야 5.6GB다.
   작업 디스크는 1.7TB가 비어 있다.
2. **7일이면 알아차린다.** 잘못된 적재는 대조 등식이 그 자리에서 잡는다.
   등식을 통과했는데 나중에 문제가 드러나는 경우를 위한 여유가 7일이다.
3. **더 길게 잡을 근거가 없다.** 원본 아카이브가 그대로 있으므로
   Bronze는 언제든 다시 만들 수 있다. 되돌리기는 편의이지 최후 수단이 아니다.

## 아직 정하지 않은 것

**Silver와 Gold는 S3 이후에 정한다.**

Bronze는 덧붙이기만 하지만 Silver의 dimension은 SCD Type 2라 `MERGE`로 계속 고쳐 쓴다.
고쳐 쓰는 테이블은 옛 파일이 훨씬 빨리 쌓인다. 그 속도를 재기 전에는 값을 정하지 않는다.

수치를 모르는 상태에서 정책부터 정하면 근거 없는 숫자가 박힌다.

## 실행

아직 실행하지 않았다. 지우면 되돌릴 수 없으므로 필요할 때 명시적으로 돌린다.

```sql
VACUUM delta.`<경로>` RETAIN 168 HOURS
```
