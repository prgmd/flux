## 범위와 검증

- 운영 Silver 버전 0, 팩트 버전 0, 아티스트 차원 버전 8의 활성 파일 목록을 고정했다. 종료 시점에도 버전이 같았다. 실험용 두 덤프 사본을 포함하지 않았으며 운영 데이터는 수정하지 않았다.
- Silver는 151,192,624건, 사용자 ID는 38,844개다. 청취 시각은 UTC 2005-02-13 11:14:27부터 2026-09-07 00:05:08까지다. 덤프 수집 기간 31일을 청취 기간으로 해석하지 않는다.
- 팩트는 151,800,271행이지만 고유 청취는 Silver와 같은 151,192,624건이다. 아티스트 연결이 있는 고유 청취는 **59,994,920건, Silver의 39.6811%**, 해당 청취 계정은 24,742개다. 순위 대상 아티스트 MBID는 311,929개다. 협업곡의 여러 아티스트 행을 전체 청취 분모에서 중복 계산하지 않았다.
- Silver의 중복 제거한 아티스트 배열을 직접 펼쳐 계산한 모든 사용자+아티스트별 횟수와 팩트의 같은 키별 횟수를 대조했다. **불일치 키 0개**다. 이번 순위 입력의 동일성을 검증한 것으로, 모든 팩트 컬럼의 동일성 검사를 뜻하지 않는다.
- 순위는 지표 값별 `RANK`로 계산했다. 동률은 공동 순위이고 다음 순번을 건너뛴다. MBID는 표시 순서를 안정화한다. 향후 Gold 마트의 동률 보조 기준은 별도 구현한다.
- 이름은 현재 차원 값을 사용한다. 동명 MBID는 합치지 않는다. 표의 RM은 `3be217fb-2b91-4911-9454-6de69751f53b`, The Beatles는 `b10bbbfc-cf9e-42e0-be17-e2c3e1d2600d`다. 다른 ID의 같은 이름은 별도 항목으로 남아 있다.
- 최초 순위와 범위 계산은 호스트 DuckDB에서 219.4초, 추가 Silver/팩트 키별 대조는 90.5초였다. 후자는 앞 계산과 일부 겹쳐 실행했다. Spark 처리 시간이나 성능 개선 실측으로 사용하지 않는다.

## 해석의 한계와 다음 단계

청취 수는 이 표본에서 기록된 청취의 양이고, 청취자 수는 이 표본에서 해당 아티스트를 들은 서로 다른 계정의 수다. 어느 쪽도 전국 또는 세계 인구의 인기도가 아니다. 최상위 계정 비중은 집중을 보여 주지만 조작이나 팬덤을 확정하는 근거는 아니다. 동일인이 만든 여러 계정은 구분할 수 없다. 여러 아티스트의 청취자 수도 서로 중복되므로 더해서 전체 사람 수로 해석할 수 없다.

현재 Silver에 30초 정책을 소급 적용하지 않았으므로 최종 정제 결과와 수치가 달라질 수 있다. RM의 기존 집중 계정처럼 재생 시간 없는 수입 기록에는 이 필터가 적용되지 않는다. 짧은 재생 격리, 반복 횟수 보존과 청취자 수 순위, 같은 곡 연결은 서로 다른 과제다.

다음은 Gold에서 UTC 청취 시각 기준의 기간별 청취 수와 고유 청취자 수를 함께 구현하는 것이다. 주간 청취자 수는 일별 합산으로 만들지 않고 해당 기간의 상세에서 다시 고유 계정을 센다. 이후 30초 기준으로 Silver와 하위 집계를 재생성하고 이 예비 결과와 비교한다.

## 재현

저장소 루트의 Git Bash에서 실행한다. 운영 표에는 쓰지 않으며 결과와 입력 명세는 저장소 밖에 둔다.

```bash
venv/Scripts/python scripts/investigations/compare_artist_rankings.py \
  --data-root C:/Users/SSAFY/Desktop/jjh/flux-data \
  --output C:/Users/SSAFY/Desktop/jjh/flux-data/scratch/artist-ranks-20261018
venv/Scripts/python -m pytest tests/test_artist_rank_comparison.py tests/test_queryrun.py -q
```

출력은 전체 아티스트 집계 `artists.json`, 버전과 입력 파일 목록 `snapshots.json`, 범위와 양쪽 상위 20개 및 사례의 `summary.json`이다. 이번 최초 실행은 추가 대조를 별도로 실행해 `source-verification.json`에 남겼고, 재현 도구에는 같은 대조를 기본 단계로 포함했다. 현재 표가 갱신되면 새 결과는 새 버전의 측정이며 위 숫자의 재현에는 저장한 기존 파일 목록을 사용해야 한다.
