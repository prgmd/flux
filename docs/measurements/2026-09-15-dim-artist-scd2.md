## 다시 돌려도 이력이 안 쌓인다

기준일만 바꿔(`2026-09-16`) 같은 원본으로 다시 병합했다.

```
병합 전  : 2,976,554행
병합 후  : 2,976,554행
늘어난 줄: 0
```

**MERGE가 멱등이다.** 값이 안 바뀌었으므로 보낼 줄 자체가 없다. 닫을 줄도
열 줄도 만들어지지 않는다.

이게 안 되면 실행할 때마다 이력이 297만 줄씩 늘어난다.

## 개명 시나리오 — 명세 게이트

실제 개명을 기다릴 수 없으므로 **주입해서** 확인했다.
대상은 MBID 순으로 첫 아티스트다.

```
대상   : 000002a0-8f8a-4320-ac61-7f60e8b44f32
원래   : Daiga Petkeviča
바꿈   : 개명 확인용 이름
```

결과다.

```
Daiga Petkeviča      2026-09-15 ~ 2026-12-25  닫힘
개명 확인용 이름       2026-12-25 ~ 9999-12-31  현재
```

| 확인 | 결과 |
| --- | --- |
| 이력이 2행이 됐다 | 통과 |
| 옛 이름이 남아 있다 | 통과 |
| 새 이름이 현재다 | 통과 |
| 현재는 하나뿐이다 | 통과 |
| 구간이 이어진다 (닫은 시각 = 연 시각) | 통과 |
| **다른 아티스트는 그대로다** (+1행뿐) | 통과 |

마지막이 중요하다. 297만 명 중 **한 명만** 이력이 늘었다. 조건이 헐거우면
관계없는 아티스트까지 새 버전이 생긴다.

### 확인 후 되돌렸다

주입은 차원을 실제로 바꾸므로 원상복구가 필요하다. Delta의 시점 조회를 썼다.

```python
spark.read.format("delta").option("versionAsOf", before_version).load(path)
     .write.format("delta").mode("overwrite").save(path)
```

복원 후 2,976,554행으로 돌아왔다. **옛 버전을 지우지 않는 Delta의 성질이
여기서 복구 수단이 된다.** 디스크를 더 쓰는 대가로 얻은 것이다.

## MERGE 도중 죽이기 — 게이트를 한 번 놓쳤다

명세 7.4의 3번이다. 컨테이너를 병합 도중 `docker kill`로 끊고 차원이
온전한지 봤다.

### 두 문장짜리 MERGE는 통과하지 못했다

처음 구현은 MERGE가 두 문장이었다. 앞 문장이 바뀐 아티스트의 현재 줄을 닫고,
뒤 문장이 새 줄을 열었다. 그 사이에서 끊었다.

```
시작 시점 parquet 79, 커밋 4
새 parquet 감지: 111개 → 즉시 죽인다
종료 후 parquet: 111
종료 후 커밋  : 5
```

커밋이 4에서 5로 **하나만** 늘었다. 앞 문장은 커밋됐고 뒤 문장은 못 했다는 뜻이다.

```
불변식: {'keys_without_exactly_one_current': 0,
        'keys_with_no_current': 1,
        'rows_with_invalid_range': 0}
```

**옛 줄은 닫혔는데 새 줄이 없는 아티스트가 하나 남았다.** 그 아티스트는
`is_current = true`인 줄이 없어 현재 이름으로 조회되지 않는다.

재실행하면 스스로 낫기는 했다(`늘어난 줄: 1`). 앞 문장은 `is_current = true`에
걸리는 줄이 없어 아무것도 닫지 않고, 뒤 문장이 빠진 줄을 넣는다. 하지만
게이트가 요구한 것은 "다시 돌리면 낫는다"가 아니라 **"반쪽 상태가 남지
않는다"**다. 다음 실행까지 그 아티스트는 사라진 채로 있다.

> Delta의 ACID는 **문장 하나**를 지킨다. 잡 전체를 지켜주지 않는다.
> 문장이 둘이면 그 사이에 틈이 있고, 틈은 언젠가 맞는다.

### 한 문장으로 합쳤다

MERGE는 대상 한 행을 한 번만 건드리므로 닫기와 열기를 한 조건에 못 쓴다.
그래서 **대상이 아니라 원본을 부풀렸다.**

| 보내는 줄 | `_merge_key` | 대상과 | 결과 |
| --- | --- | --- | --- |
| 바뀐 아티스트 | `artist_mbid` | 만난다 | 옛 줄을 닫는다 |
| 바뀐 아티스트 | `NULL` | 못 만난다 | 새 줄을 연다 |
| 처음 보는 아티스트 | `NULL` | 못 만난다 | 새 줄을 연다 |

NULL은 어떤 값과도 같지 않다는 SQL의 성질을 **일부러** 쓴다. 다른 곳에서는
`eqNullSafe`를 쓰게 만든 함정이었던 것이 여기서는 "반드시 안 만나는 키"를
만드는 도구가 된다.

Delta 로그의 커밋 메트릭이 합쳐진 것을 보여준다. 같은 개명을 처리했는데
커밋 수가 다르다.

```
두 문장  버전 1  MERGE  numTargetRowsUpdated: 1,  numTargetRowsInserted: 0
         버전 2  MERGE  numTargetRowsUpdated: 0,  numTargetRowsInserted: 1

한 문장  버전 7  MERGE  numTargetRowsUpdated: 1,  numTargetRowsInserted: 1
```

**아래는 끊을 자리가 없다.**

### 다시 죽여봤다 — 두 지점에서

| 죽인 지점 | 커밋 | 이력 줄 | 대상 아티스트 | 불변식 |
| --- | ---: | ---: | --- | --- |
| 새 parquet이 보이자마자 (쓰기 중) | 9 → **9** | 2,976,554 | 1행, 현재 | 전부 0 |
| parquet 증가가 멈춘 뒤 (커밋 직전) | 9 → **10** | 2,976,555 | 2행, 이력 완성 | 전부 0 |

**둘 다 반쪽이 아니다.** 앞은 커밋이 없어 아무 일도 일어나지 않았고, 16개
쓰인 parquet은 로그에 없으므로 읽히지 않는다. 뒤는 커밋이 통째로 들어가
닫기와 열기가 함께 반영됐다.

```
Daiga Petkeviča      2026-09-15 ~ 2026-12-25  닫힘
개명 확인용 이름       2026-12-25 ~ 9999-12-31  현재
```

**중간이 없다.** 그것이 원자성이다.

확인 뒤 시점 조회로 2,976,554행 상태로 되돌렸다.

## 추적 대상을 둘로 좁혔다

`name`과 `sort_name`만 바뀔 때 새 버전을 만든다. 나머지는 Type 1로
현재 줄의 값만 갱신한다.

근거는 실측이다(`2026-09-15-mb-artist-load.md`).

| 컬럼 | 채워진 비율 |
| --- | ---: |
| `name`, `sort_name` | **100%** |
| `type` | 77.39% |
| `country` | 37.78% |
| `begin_date` | 20.17% |
| `end_date` | 5.22% |

`country`를 추적하면 **빈칸이 채워지는 것도 "바뀐" 것**이 된다. 그러면 이력의
대부분이 개명이 아니라 MusicBrainz 편집자가 빈칸을 메운 기록이 되고,
이 차원이 답하려는 질문("그때 뭐라고 불렸나")에서 멀어진다.

## 아직 재지 않은 것

- **이력이 실제로 얼마나 쌓이는가.** 다음 릴리스를 받아 병합해야 안다.
  지금은 주입한 한 건뿐이다
- **`valid_to`를 먼 미래로 둔 선택의 대가.** `9999-12-31`이 파티션이나
  통계에 어떤 영향을 주는지 안 봤다

## 재현

```
docker run --rm -m 10g -v <데이터 루트>:/data \
  -e FLUX_STORAGE_ROOT=file:///data ... flux-spark \
  python scripts/gold_dim_artist.py --at 2026-09-15

docker run ... flux-spark python scripts/gold_rename_drill.py
```

강제 종료는 `--keep`을 붙여 돌린 뒤 호스트에서 차원 폴더의 parquet 개수를
지켜보다가 `docker kill`로 끊었다. 새 parquet이 보이자마자 끊으면 쓰기 중이고,
개수 증가가 멎은 뒤 끊으면 커밋 직전이다. 끊은 뒤에는 `_delta_log`의 커밋
수와 `dim_artist.invariants`를 본다. 확인이 끝나면 시점 조회로 되돌린다.

결과는 데이터 루트의 `measurements/dim-artist-merge.json`,
`measurements/dim-artist-rename-drill.json`에 있다.
