# 월별 Gold 7개 마트의 dbt 표본 대조

## 입력과 실행 범위

2026-10-23에 P3의 나머지 월별 아티스트, 아티스트 내 곡, 버전, 계정 및 식별 커버리지를 추가했다. 성공 출력은 `data/dbt-monthly-20261023-r2`다. [P0](2026-10-22-governance-baseline.md)의 월별 6,469행과 113,368회, 곡 사전 344행과 라벨 100행 및 공식 크레딧 46행을 그대로 복사했다. 새 표본을 뽑거나 승인 및 버전 정책을 바꾸지 않았다.

Python 3.11.9, dbt-core 1.11.16, dbt-duckdb 1.11.0과 DuckDB 1.5.5의 기존 분리 환경을 사용했다. 운영 Delta를 읽는 source 대신 실험 DB의 pinned 표 4개만 등록했다. 실행 SQL 프로젝트도 출력 안에 복사해 지문을 남겼다. 이전 두 마트 출력과 기존 14개 Gold Parquet도 보존했다.

7개 전체를 P0 기대 Parquet, 기존 SQL 생성기 및 Python 독립 집계와 각각 대조해 불일치 0을 확인했다. 모든 키와 컬럼, 자료형과 정수 및 NULL 상태를 검사하고 실수는 상대 및 절대 허용 오차 1e-12를 적용했다. 같은 입력으로 다시 build한 결과도 일치했다. 등록된 source 표 내용과 복사 입력, 원래 P0 자료 및 실행 프로젝트 지문은 유지됐다. `completed=true`, `production_applied=false`, `promotion_ready=false`다.

## 지표 의미의 회귀 검사

제어 표본은 사용자+MSID+월 8행과 24회로 구성했다. 여러 MSID를 가진 같은 곡과 공식 공동 크레딧, 한 아티스트의 여러 곡을 같은 계정이 듣는 경우를 함께 넣었다. 1월 아티스트 a는 청취 12회와 계정 3개, 최대 한 계정 9회이며 참여자 b는 6회다. 아티스트 합은 18회지만 연결된 실제 청취는 12회다. 참여자마다 횟수를 부여하는 집계와 연결 여부만 세는 커버리지를 구분했다.

같은 아티스트의 두 곡은 각각 6회와 계정 2개다. 곡 청취 비중은 각각 0.5, 계정 도달률은 각각 2/3이며 공동 순위 1이다. 계정 도달률 합을 1로 강제하지 않는다. 버전 unmarked는 13회와 계정 3개, 최대 한 계정 9회로 합산된다. Sped Up+Remix 라벨은 별도로 남는다. 계정 u1은 9회와 곡 2개 및 최다 곡 비중 5/9이며 곡 식별 no_mbid 상태는 8회와 계정 2개를 보존한다. 이름순 표시는 명시한 ORDER BY로 검사했다.

## 테스트와 문서

두 정상 build는 각각 모델 14개와 데이터 테스트 81개가 성공했다. 총 95개 노드에 실패와 경고 및 건너뛰기는 없었다. staging 뷰 4개와 사용자별 중간 뷰 3개 및 최종 마트 7개다. 합계 보존 검사는 곡과 커버리지, 버전, 계정 및 식별 상태를 월별로 대조하고 아티스트 합에는 적용하지 않는다. 아티스트 및 버전의 집중도와 최대 계정 비중도 유효 범위를 검사한다.

정상 DB를 복사한 오류 사본 10개에서 월별 키 복제, 0회, 사전 누락, 잘못된 곡 순위와 연결률 및 아티스트 최대 횟수, 아티스트 내 곡 비중, 버전 청취 비중, 계정 곡 수와 식별 상태 횟수를 모두 검출했다. 기대 테스트 fail과 종료 코드 1을 요구하며 SQL error를 검출 성공으로 세지 않았다. 정상 DB 지문과 마지막 7개 마트 대조도 유지됐다. `drill_passed=true`, `scenarios_checked=10`, `canonical_database_unchanged=true`다.

docs generate에서 source 4개와 모델 14개를 확인했다. 최종 7개 마트의 직접 부모 관계와 최종 컬럼 75개의 설명이 manifest 및 catalog에 대응한다. index.html도 생성했다. 브라우저 렌더링 검수와 외부 Spark 및 검수 저널의 자동 계보는 포함하지 않는다. 실행 시간은 debug 4.381초, build 10.959초, rebuild 11.176초, docs 8.586초였다. 작은 표본의 실행 시간이며 전체 Silver의 예상 처리 시간으로 쓰지 않는다.

관련 호스트 회귀는 14개 테스트 파일의 91개가 22.13초에 통과했다. 별도 dbt 환경의 실제 도구 통합 검사 1개도 최종 122.62초에 통과했다. 제어 표본의 의미 검사와 두 build 및 docs 생성, 오류 주입 10개를 포함한다. Spark와 클러스터 테스트 또는 전체 저장소 테스트를 모두 실행한 결과로 확대하지 않는다.

## 실패 확인과 남은 범위

구현 전 빠른 테스트에서 7개 통과와 7개 실패를 확인했다. 비교 대상이 기존 2개에 머물렀고 새 5개 표가 없어서 실패했다. 구현 후 해당 파일의 14개가 통과했다. 샌드박스 기본 임시 디렉터리 생성 실패는 검사 대상의 오류와 구분했고, 이후 Git에서 제외된 data 아래의 새 basetemp로 실행했다.

이 결과는 월별 7개 마트의 고정 표본 이전이다. 연간 7개 마트, 전체 규모 생성과 성능, Gold 영향 기간 갱신 및 GX와 운영 승격은 남아 있다. 기존 연결률을 개선하거나 미확인 곡을 새로 합친 작업은 아니다. 재현 명령은 [실행 문서](../dbt_pilot.md)를 따른다.
