# dbt Gold의 기간 교체와 복구 검증

## 입력과 범위

P0 월별 6,469행과 113,368회 및 기존 dbt 14개 마트에서 시작했다. 실제 새 Delta 버전이 아니라 별도 사본의 횟수, 삭제 및 메타데이터와 정책 태그를 통제한 실험이다. 기본 전체 생성 경로와 지표 수식은 유지하고 명시적인 기간 교체 설정을 추가했다. 실제 Silver CDF 읽기와 운영 체크포인트 및 전체 규모는 후속이다.

## 실제 표본 결과

| 단계 | 영향 기간 | 전체 청취 수 | 내부 경과 |
| --- | --- | ---: | ---: |
| 2005-05 한 행에 1회 추가 | 한 월과 2005년 | 113,369 | 33.496초 |
| 같은 입력 재실행 | 없음 | 113,369 | 3.751초 |
| 2026-10 전체 170개 키 삭제 | 한 월과 2026년 | 112,416 | 31.710초 |
| 라벨과 크레딧 이름 제어 변경 | 220개월과 21년 | 112,416 | 32.261초 |
| 정책 태그 변경과 전체 전환 | 254개월과 22년 | 112,416 | 33.022초 |

각 단계의 14개 최종 마트가 Python 독립 전체 계산 및 기존 Gold SQL 전체 계산과 모든 키와 값에서 일치했다. 첫 갱신에서 영향 밖의 14,481행, 재실행에서 14,500행, 삭제 단계에서 12,195행도 이전 값과 같았다. 행 수는 14개 표의 비교 행 합이며 원본 청취 행 수가 아니다. 연간 값은 월별 고유 수와 비중의 합이 아니라 사용자별 연간 기여에서 계산했다.

매 실제 build에서 모델 24개와 데이터 검사 145개가 통과했다. 재실행은 dbt를 호출하지 않고 기존 결과와 원본 지문을 대조했다. 대표 이름 변경이 넓은 기간에 영향을 줄 수 있어 보수적인 범위를 유지했다. 이 작은 목적 표본의 영향 기간 수를 전체 데이터 비율로 사용하지 않는다.

시간은 각 새 출력 경로를 만든 뒤의 내부 경과다. 이전 사본의 선행 무결성 검사와 표본 읽기는 일부 제외한다. 첫 단계 dbt 명령은 28.499초였다. 초기 기준 DB는 10,235,904바이트, 갱신과 재실행 DB는 각각 13,381,632바이트, 삭제 DB는 14,954,496바이트였다. DB는 입력과 전체 마트를 함께 담으므로 삭제가 파일 크기의 즉각 감소를 보장하지 않는다. 별도 복사 경로들의 합과 logs 및 컴파일 산출물은 이 크기와 구분한다.

## 실패와 복구

실제 통합 시나리오는 정상 최초 생성과 두 변경 및 재실행, 마지막 연도의 삭제, 잘못된 SQL로 일부 모델 실패 후 새 사본 재시도, dbt build 뒤 프로세스 종료 코드 86과 같은 입력 복구를 포함했다. 실패와 종료 사본은 completed=false로 유지됐고 다음 처리의 이전 기준으로 거부했다. 이전 완료 DB는 그대로였다. 중단 사본을 이어서 직접 고치는 방식이 아니라 마지막 완료 사본에서 새 출력으로 재실행했다.

SQL에 영향을 줄 수 있는 잘못된 월 문자열과 누락된 연도 목록, bool이 아닌 증분 설정은 실제 dbt 컴파일로 거부했다. 전체 run_results의 노드 집합을 manifest와 대조해 누락 및 중복이나 성공하지 않은 검사가 있으면 완료하지 않는다.

첫 실제 6,469행 입력에서 행별 executemany가 수분 동안 입력 교체 단계에 머물렀다. 해당 실험 프로세스만 식별해 중단하고 미완료 경로를 보존했다. 원래 DB 지문은 유지했다. 스키마를 지정한 JSON의 일괄 읽기로 바꾸고 실제 표본의 전체 단계를 다시 검증했다. 원본 DB나 품질 검사를 줄이는 방식으로 해결하지 않았다.

## 테스트와 남은 범위

관련 호스트 회귀 89개가 72.06초에 통과했고 최종 입력 가드 및 영향 규칙 24개도 통과했다. 실제 기간 교체와 복구 시나리오 및 컴파일 거부 검사는 합계 4개가 308.34초에 통과했다. 하나의 통합 시나리오 안에서 여러 실제 build와 프로세스 종료 및 재시작을 수행한 수치다. 새 소형 결과의 파일, 이전 결과와 입력 및 실행 프로젝트 지문도 확인했다.

운영 Bronze와 Silver 및 기존 Gold, 원래 dbt 기준 DB는 변경하지 않았다. R9 전수 연결이나 사람 승인을 추가하지 않았고 버전 분리는 유지했다. 아직 실행하지 않은 것은 실제 Silver CDF 구간의 통합, 대규모 영향 기간 처리와 성능 및 보존 만료, 운영 전체의 품질 차단과 조회 대상 교체, 연속 운영이다. [실행과 동작](../gold_increment.md)을 따른다.
