# 실제 Silver CDF와 Gold의 사본 검증

2026-10-23에 보관한 실제 덤프 접두부 및 고정 Bronze 표본의 완료 실험본을 새 경로로 복사했다. 운영 데이터 경로는 컨테이너에 마운트하지 않았고 이전 실험본은 읽기 전용으로 연결했다. [연결 방식](../silver_cdf_gold.md)에 따라 실제 Spark CDF와 dbt를 분리해 실행했다. 전체 Silver나 새 덤프 전체를 처리한 결과는 아니다.

## 입력과 실제 변경분

초기 Bronze는 실제 덤프 표본 256행과 이전 제어 기록 1행을 포함한 257행이며 월별 Silver 256행, 총 257회가 기준이다. 원본을 읽기 전용으로 다시 집계해 이 구성을 확인했고 복제 대상으로 고른 행은 실제 덤프 기록이었다. 이 사본에 청취 한 건을 추가하고 시각을 다른 연도로 옮긴 뒤 삭제했다. 값 변화 없이 버전만 진전시키는 변경과 복구용 재삽입도 만들었다. 시험을 위해 제어한 변경이며 새로 관측한 청취로 해석하지 않는다.

Silver 월별 표의 Delta 버전은 15에서 20, 메타데이터와 격리는 각각 11에서 16까지다. 각 시점의 세 표는 같은 Bronze 처리 위치에 도달한 뒤 고정했다. 일곱 시점에서 고정 Bronze 버전의 Python 및 전체 Spark 재집계와 대조해 월별 값과 격리 및 메타데이터의 불일치 0을 확인했다.

실제 CDF는 update_preimage 3행, update_postimage 3행, insert 1행, delete 1행이다. Spark가 시작 다음 버전부터 종료 버전까지 실제로 읽고, 같은 버전의 변경 전후 전체 Silver를 함께 내보냈다. Gold 입력에 이 변경분을 적용한 결과가 종료 버전의 Silver와 같아야 다음 단계로 진행한다.

각 결과는 월별 및 연간 14개 마트를 대조했다. Python 독립 전체 계산과 기존 SQL 전체 계산, 변경하지 않은 기간의 행도 검사했다. 초기값은 동결한 기대값과도 대조했다. 메타데이터 커밋에서는 처리 위치가 진전했지만 마트를 다시 생성하지 않았다. 같은 CDF 묶음 재투입도 변경을 다시 적용하지 않았다.

실제 프로세스 종료 코드 86을 두 번 확인했다. Gold build 직후 종료에서는 내부 Gold도 미완료였고, 처리 위치 저장 직전 종료에서는 내부 Gold가 완료돼 있었다. 두 경우 모두 바깥 완료 표시는 거짓이며 cursor.json이 없었다. dbt의 실행 결과에는 모델 24개와 검사 145개가 모두 성공한 것을 별도로 확인했다. 실패 사본을 다음 기준으로 쓰는 행위와 변경 범위 건너뛰기 및 내보낸 파일 변조도 차단했다.

## 귀속과 버전의 검증 범위

이 실제 접두부 표본에는 제한된 기준 Gold의 공식 크레딧과 겹치는 청취가 없어 아티스트 마트가 비었다. 0을 운영 커버리지로 해석하지 않는다. 미검수 곡은 MSID 키와 unreviewed 상태로 청취 및 커버리지에 보존했다. 원래 운영 Gold의 귀속을 지우거나 변경한 결과가 아니다.

비어 있지 않은 귀속은 메인과 피처링 두 크레딧을 가진 별도 합성 표본에서 실제 Delta CDF와 dbt로 검증했다. 수정 후 각 아티스트는 3회와 계정 1개이며 전체 연결 청취는 3회다. 연간 값과 재실행도 대조했다. 합성 표본의 a와 b는 테스트용 ID이며 실제 아티스트의 사실 검수 결과가 아니다. 기본 테스트에서는 새 MSID의 Sped Up과 Remix 및 상충하는 Live 표기를 보존하고 확인하지 않은 MBID로 자동 연결하지 않는 것도 확인했다.

## 테스트와 시간

| 구분 | 결과 | 경과 |

| 최소 개발 환경 전체 회귀 | 990 passed, 20 skipped, 12 deselected | 208.90초 |
| 관련 기본 검사 | 52 passed | 13.07초 |

| 비어 있지 않은 합성 크레딧 연결 | 1 passed, 1 deselected | 201.45초 |

테스트 경과는 pytest 출력 기준이다. 52개는 전체 기본 회귀에 포함되므로 별도 성공 수로 더하지 않는다. 기본 실행에서 빠진 Spark와 dbt를 전용 환경에서 명시 실행했다. 실제 CDF 내보내기가 없으면 Gold 연결 테스트는 skip한다.

Spark 4.2.0의 실제 표본 생성 컨테이너는 903.73초가 걸렸으며 복사와 일곱 번의 전체 Silver 대조 및 CDF 내보내기가 포함된다. 컨테이너는 CPU 2개와 메모리 4GiB로 제한했고 OOM 없이 종료했다. 이 시간은 변경 한 건의 순수 처리 지연이나 전체 데이터의 시간 예측값이 아니다. dbt는 기존 Python 3.11.9 격리 환경에서 실행했다. SQL 지표와 Python 처리 규칙의 지문이 달라지면 이전 사본의 증분을 거부한다.

## 남은 범위

이번 완료는 소형 실제 Silver CDF에서 Gold로 이어지는 버전 기반 배치 경로다. 전체 80,563,985행의 대규모 증분과 새 덤프 전체, 실제 보존 기간 만료, 운영 조회 대상 전환 및 다중 작성자의 전역 처리 위치 조정은 아직 검증하지 않았다. 기존 MSID의 공식 매핑 및 대표 이름 보정은 별도의 버전 고정 입력으로 확장한다. 관측과 독립 복원 및 카탈로그, Airflow와 실제 연속 운영도 후속이다.


코드 94f530f의 [GitHub 자동 검사](https://github.com/prgmd/flux/actions/runs/39912952332)도 기본 989개와 dbt 7개 및 GX 11개가 통과했다. 원격의 기본 21개 skip과 로컬 20개의 차이는 로컬 explorer 실제 표본 한 개다. CI의 dbt 7개는 기존 기간 교체 및 복구 회귀이며, 실제 CDF 연결 두 검사는 위의 로컬 전용 통합 결과다.
