# P0 입력 고정과 Gold 비교 기준

2026-10-22 실측. [확장 계획](../data_governance_plan.md)의 입력 및 비교 표본 준비 결과다. 기존 검증본은 보존하고 로컬 `data/governance-baseline-20261022-r2`에 작은 별도 기준 자료를 만들었다. 도구 설치, CDF 활성화와 운영 데이터 변경은 하지 않았다. 입력 기준은 준비됐으며 P2용 새 연속 입력 확보와 dbt 및 GX 실행 호환성 확인은 별도 잔여 항목이다.

## 고정한 입력

| 대상 | Delta ID | 버전 | 활성 파일 | CDF |
| --- | --- | ---: | ---: | --- |
| 통합 Bronze | bee002a0-8961-455e-b032-bf1c65c57136 | 0 | 277 | 비활성 |
| monthly_user_recordings | 38b0253b-2ec4-4e7b-a08f-c63ec589e61e | 0 | 261 | 활성 |
| recording_metadata | 25e9603c-4a33-4362-a848-fd9e7ec03711 | 0 | 16 | 활성 |
| invalid_listens | 25192d20-9ce5-468a-bb1b-9a1b147f476d | 0 | 9 | 활성 |

Silver 세 표의 처리 위치는 같은 Bronze ID와 v0, 사용자 이름+MSID+UTC 월, minimum_ms_played=30000, policy_version=1을 가리켰다. 실제 Bronze ID 및 버전과의 일치도 확인했다. 원본 Delta JSON을 엄격하게 읽어 지정 버전의 add와 remove를 적용했고 활성 경로, 파일 크기와 수정 시각 및 로그 SHA-256을 고정했다. 최신 버전을 다시 조회해 표본을 구성하지 않는다. 현재 고정기는 v0부터 대상 버전까지 완전한 JSON 이력이 필요하며 체크포인트만 남은 입력과 deletion vector는 지원하지 않고 실패한다.

기존 결과 기준은 최초 Gold가 아닌 공식 귀속을 갱신한 `data/gold-attribution-20261019`다. 귀속 정책은 separate-artist-v1이고 대응하는 `data/artist-attribution-20261019`를 고정했다. Gold 및 조사본의 Silver 지문과 Gold가 기록한 조사본 해시를 대조했다. 공식 MusicBrainz 스냅샷과 redirect 매니페스트, 최근 R9 표본의 근거 및 판단 파일도 조회 기준으로 고정했다. R9 사람 승인은 0이고 실험용 판단을 이 기준의 운영 매핑으로 적용하지 않았다.

기준의 계정 키는 user_name이다. 기존 Spark 기간별 마트의 user_id와 혼합하지 않는다. 순위는 월별 및 연간 Gold의 청취자 기준 RANK와 공동 순위이며, 기존 Spark 기간별 순번과 직접 대조하지 않는다.

## 표본의 범위

기존 악센트 검수 관측과 과거 Gold 독립 검수의 곡, Live 및 Remix와 Sped Up 사례에서 시작했다. 선택한 Gold 곡 키의 MSID를 모두 포함하고 그 MSID들의 모든 월별 기록을 읽었다. 같은 곡을 구성하는 MSID 일부만 뽑아 기존 곡의 횟수를 과소 집계하지 않는다. 무작위 표본이나 전체 정확도 추정용 표본은 아니다.

| 항목 | 실측 |
| --- | ---: |
| 월별 입력 행 | 6,469 |
| play_count 합 | 113,368 |
| 원본 MSID | 344 |
| 기존 Gold 정책의 곡 키 | 100 |
| play_count가 1보다 큰 월별 행 | 2,505 |
| 여러 MSID를 가진 곡 키 | 18 |
| 곡 식별 미확정 키 | 75 |
| 여러 공식 참여 아티스트가 있는 곡 | 4 |
| 같은 계정 및 곡이 여러 달에 있는 묶음 | 807 |
| 관측 MBID가 NULL인 메타데이터 행 | 155 |
| 여러 관측 MBID가 있는 MSID | 10 |

곡 키 100개는 최종적으로 정확한 실제 곡 100개라는 뜻이 아니다. 현재 정책의 미확정 MSID 키도 포함한다. 관측된 버전 조합은 acoustic, live, remix, sped_up과 unmarked다. 원문과 상충 근거를 보존했고 새로운 곡 연결 규칙을 추가 적용하지 않았다.

별도 Bronze 첫 활성 파일의 256행과 격리 첫 파일의 64행도 원문과 함께 보관했다. Bronze 탐색 표본의 재생 시간은 미기재 128행, 기재 128행이었다. 기존 Python 판정으로 255행 통과, 1행은 30초 미만 격리 대상이다. 격리 표본 64행은 모두 재생 시간 기재 및 30초 미만 사유로 재판정됐다. Bronze 표본 256행 모두 적재 시점보다 30일 이상 과거의 청취였다. 이는 품질 규칙용 별도 탐색 표본이며 월별 표본의 원래 사건 목록이나 전체 원천 비율을 뜻하지 않는다.

## 두 종류의 기대값

첫째는 작은 입력만으로 재현하는 14개 마트다. 고정한 조사본에서 기존 build_dimension과 build_period를 실행하고 모든 값을 별도의 Python 사전 누적과 대조했다. Python은 SQL 변환이나 집계 함수를 호출하지 않고 사용자별 횟수에서 고유 계정, 순위, 집중도와 비중을 직접 계산한다. 저장된 Parquet을 다시 읽어 모든 키와 컬럼을 비교했다. 정수와 문자열 및 NULL은 정확히 비교하고 부동소수 지표만 상대 및 절대 오차 1e-12를 허용한다.

| 마트 | 월별 행 | 연간 행 |
| --- | ---: | ---: |
| song_metrics | 1,445 | 322 |
| artist_metrics | 839 | 152 |
| artist_song_metrics | 888 | 178 |
| variant_metrics | 269 | 29 |
| listener_metrics | 6,048 | 3,328 |
| coverage | 255 | 22 |
| identity_coverage | 635 | 90 |

둘째는 선택한 곡의 기존 전체 Gold 참조다. 월별 및 연간 곡 결과 1,767행을 별도 보관하고 순위 두 컬럼을 제외한 모든 값이 고정 입력의 독립 계산과 일치하는지 확인했다. 곡 키에 속한 모든 MSID와 월을 포함했으므로 곡별 지표의 분모는 원래와 같다. 원래 전체 순위도 파일에 남기지만 표본 안의 순위와 같다고 검사하지 않는다. 전체 순위는 표본 밖 곡의 영향도 받는다.

아티스트와 커버리지 및 계정의 표본 지표는 표본의 범위에 대한 값이다. 기존 전체 Gold의 해당 지표와 모두 같다는 검증은 아니다. P3의 전체 이전에서는 같은 전체 입력으로 14개 마트를 다시 대조해야 한다.

## 저장과 재현

`source_context.json`은 네 Delta 표의 ID, 버전과 활성 파일, 원천 및 기존 결과 파일 34개의 SHA-256, 적용 정책과 코드 지문을 저장한다. 실행 코드 여섯 파일도 code 아래 복사했다. 공식 원본 TSV와 덤프 압축 파일 전체를 이번에 다시 해시한 것은 아니다. 공식 추출 매니페스트의 지문을 보존하고 덤프는 과거 기록 체크섬과 현재 크기 및 수정 시각, 실제 헤더를 구분해 저장했다. 대형 Bronze와 Silver 전체 데이터 파일에는 로그 지문 및 경로, 크기와 수정 시각 검사를 사용하고 복사한 표본 파일에는 SHA-256을 적용했다.

inputs에는 월별 입력, 조사본과 크레딧, 곡 사전 및 메타데이터, Bronze와 격리 탐색 표본이 있다. expected에는 작은 입력의 14개 마트, full_gold_reference에는 원래 전체 곡 결과가 있다. 선택 규칙과 특징, 호환 검증 항목과 덤프 목록은 각각 selection, features, compatibility와 dump_inventory JSON에 둔다. result.json은 모든 검증 및 입력 불변 검사 후에만 completed=true가 되고 산출물 42개 지문을 보관한다. 기준 자료 전체는 954,593바이트이며 원본과 이전 데이터의 보관량은 포함하지 않는다.

Git Bash 재검증 명령:

```bash
PYTHONPATH=src venv/Scripts/python scripts/verify_governance_baseline.py --baseline data/governance-baseline-20261022-r2
```

원본 Bronze나 Silver 및 전체 Gold를 읽지 않고 자료 자체의 해시와 Python 재계산으로 14개 마트를 재검증했다. 불일치 0이다. 새 생성은 `scripts/prepare_governance_baseline.py --help`의 경로를 지정하고 존재하지 않는 출력 경로를 사용한다. 기존 기준 자료를 덮어쓰지 않는다. 전체 생성은 2스레드와 DuckDB 메모리 한도 4GB에서 86.68초였다. 성능 비교 실험은 아니다.

## 수집 경로와 남은 조건

로컬에 보존한 실제 ListenBrainz 압축 덤프 33개의 START_TIMESTAMP와 END_TIMESTAMP 및 첫 청취 레코드를 확인했다. 31개는 연속이고 이후 10월 1일과 18일 덤프는 각각 독립 구간이다. 연결되지 않는 구간은 다음과 같다. 시각은 UTC다.

| 이전 종료 | 다음 시작 |
| --- | --- |
| 2026-09-07 00:00:02.346174 | 2026-09-30 00:00:02.933860 |
| 2026-10-01 00:00:03.466019 | 2026-10-17 00:00:03.296056 |

일련번호가 건너뛰었는지가 아니라 실제 구간 경계를 대조했다. 새 수집 경로는 구간의 모든 덤프를 대상으로 하는 fetch_incremental_range.py를 선택한다. 최신 일련번호 하나를 고르는 수집 코드를 이번에 수정하지 않았다. 새 다운로드나 서버의 최신 목록 조회는 수행하지 않았으며 현재 목록을 미래 P2 입력의 연속 확보 완료로 표시하지 않는다. 새 연속 입력은 받을 때마다 헤더와 실제 내용 및 체크섬을 확인해야 한다.

호스트 가상환경은 Python 3.14.6과 DuckDB 1.5.5이며 dbt와 GX 및 Soda는 설치하지 않았다. compatibility.json의 패키지 목록은 호스트 기준이고 기존 Spark 컨테이너의 설치 여부를 판정한 결과가 아니다. 도구의 입력 읽기, 모델 및 테스트 실행, 문서와 카탈로그 산출물 호환성은 후속 스모크 항목으로 남겼다. 현재 baseline_ready=true, p0_collection_ready=false, tool_compatibility_pending=true다.

## 검증 범위

새 테스트 10개와 관련 기존 회귀 합계 105개가 통과했다. 모듈 부재 실패부터 확인하고 고정 버전 유지, 원본 변경, 깨진 로그와 경로 이탈 및 누락 파일, 중복 키와 변조 값, 14개 독립 집계와 기존 곡 결과, 전체 및 표본 순위 차이, 미완료 및 변조된 기준 자료, 실제 압축 헤더와 비어 있는 덤프 및 구간 누락을 검사했다. 실제 추출 중 발견한 COPY의 목록 매개변수 및 출력 경로 혼동은 재현 테스트로 고정하고 수정했다. 첫 실패 출력은 완료본으로 사용하지 않으며 성공한 r2만 기준으로 삼는다. Spark나 CDF를 실행하거나 dbt로 이전한 검증은 아니다.
