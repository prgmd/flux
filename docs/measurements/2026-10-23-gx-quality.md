# GX 고정 표본과 결과 전환 차단 검증

2026-10-23의 출력은 data/gx-quality-20261023-r2, 오류 사본은 data/gx-drill-20261023이다. P0의 고정 월별 6,469행과 113,368회 및 같은 입력의 dbt 월별과 연간 14개 마트를 사용했다. Python 3.11.9, GX Core 1.24.1과 Pandas 3.1.0, DuckDB 1.5.5의 별도 환경이다. 기존 운영과 Spark 및 dbt 환경은 유지했다.

## 실제 검사 결과

GX의 DQ003 필수 키와 월 8개, DQ004 복합 키 유일성 1개와 DQ005 정수 횟수 3개, 합계 12개 Expectation이 통과했다. P1 독립 계약도 PASS 14, SKIP 1과 WARN 2다. 상세 표를 보유하지 않은 DQ008은 적용 제외이며 수집 연속성 DQ016과 통계 기준 보정 DQ017은 기존 경고로 남겼다. 규칙 17개의 담당을 명시했고 월별 표에 없는 재생 시간이나 새 사람 승인을 만들지 않았다.

실제 GX Checkpoint와 세 Validation Definition 및 UpdateDataDocsAction을 실행해 Data Docs와 원래 검증 JSON을 저장했다. BOOLEAN_ONLY 결과에 실패 행이 포함되지 않는지 실제 테스트로 확인했고 analytics를 껐다. 입력 사본에는 계정 원문이 있으므로 로컬에만 둔다. 문서 파일 생성과 구조를 확인한 범위이며 로컬 file URL 정책으로 브라우저 시각 검수는 수행하지 못했다.

| --- | --- | --- | --- |
| 정상 대조 | 통과 | 통과 | sandbox 사본만 성공 |

오류 여섯 건에서 이전 조회 대상 파일의 바이트가 유지됐고 정상 대조를 먼저 확인했다. 실패한 엔진 자체를 데이터 오류 탐지로 잘못 세지 않도록 실제 GX 실행 완료와 규칙별 판정을 함께 검사했다. 순위 오류는 GX가 담당한 세 규칙 범위 밖이므로 독립 계약이 탐지하는 것이 기대 동작이다.

## 시간과 용량

실제 validate 내부 경과는 8.146초다. P1과 GX 실행 및 로컬 문서와 파일 지문을 포함하고 Python 기동, 선행 표본 적재와 후보 DB의 초기 해시는 제외한다. 출력 49개 파일은 11,167,624바이트이며 가상환경과 실패 사본 및 실험 사본들의 합이 아니다. 전체 Silver의 성능으로 환산하지 않는다.

호스트 관련 회귀 66개가 34.24초에 통과했다. 실제 GX 통합 11개는 33.48초에 통과했다. 중복과 빈 키 외에 숫자형 키, 소수와 bool 횟수, 잘못된 월 및 순위, 엔진 예외와 Data Docs 미생성을 포함한다. 기본 pytest에서 gx 표시는 제외하며 전용 환경의 -m gx로 실행한다.

## 발견한 실패와 수정

처음에는 없는 모듈의 수집 실패를 확인했다. 구현 뒤 GX CheckpointResult에 없는 to_json_dict 호출과 옛 suite 메타데이터 키 접근이 실패했다. 설치한 1.24.1의 소스에서 Checkpoint 결과와 개별 Validation 결과의 직렬화 API가 다르고 suite_name이 독립 속성임을 확인해 수정했다. 부정 테스트에도 엔진이 실제로 실행됐는지와 담당 규칙의 실패 여부를 요구했다.

dbt 결과의 input_manifest_sha256은 P0 result.json이 아니라 해당 결과의 inputs.json 지문이었다. 두 문서의 연결을 각각 검증하도록 수정했고 파일 변조를 거부하는 회귀를 추가했다. 범위 제한 테스트의 COPY에서 범위 값과 파일 경로를 함께 바인딩하자 DuckDB 내부 오류가 발생해 기존 literal 경로 처리와 쿼리 매개변수를 분리했다. 기본 Windows 임시 경로 접근 오류는 저장소의 새 basetemp로 분리했다. 이 실패들은 검사나 보호 조건을 느슨하게 해서 통과시키지 않았다.

## 완료 경계

기준 자료와 기존 후보 DB를 전후 해시로 확인했고 production_applied 및 promotion_ready는 거짓이다. 결과 전환 도구는 명시한 sandbox_root 안에서만 시험했다. 실제 운영 조회 대상의 교체, 다중 승격 프로세스의 경쟁 제어, GX Spark 및 전체 SQL 엔진, 통계 경고의 운영 보정과 Gold 증분은 후속이다. [실행과 규칙별 담당](../gx_quality.md)을 따른다.
