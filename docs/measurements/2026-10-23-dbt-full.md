# 전체 Silver의 dbt Gold 전수 검증

## 입력과 완료 범위

2026-10-23의 성공 출력은 `data/dbt-full-20261023-r3`다. [P0 고정 버전](2026-10-22-governance-baseline.md)의 전체 월별 Silver v0, 사용자 이름+MSID+UTC 청취 월 80,563,985행과 157,351,363회를 사용했다. 같은 입력의 기존 Gold `data/gold-attribution-20261019`와 같은 곡 및 공식 귀속 정책으로 대조했다. 곡 사전 22,293,848행과 라벨 21,174,963행, 크레딧 1,952,891행을 별도 DuckDB에 복사했다. 이 사전 행 수를 최종 곡 수로 해석하지 않는다.

첫 전체 build는 모델 15개와 검사 86개가 성공하고 연간 기여 검사 1개가 메모리 오류, 67개가 건너뛰어졌다. 실패한 검사와 건너뛴 67개를 새 경로에서 복구해 합산 상태의 모델 24개와 검사 145개가 모두 통과했다. 모델은 staging 뷰 4개와 중간 테이블 6개, 최종 마트 14개다. 표본과 같은 SQL을 사용하고 실행 프로젝트 사본에서 중간 결과만 테이블로 저장했다. 기존 모델 SQL과 표본 실행 프로파일은 유지했다. 공통 source 및 모델 설명만 표본과 전체 입력에 모두 맞는 표현으로 보완했다. 운영 Bronze 및 Silver, 격리와 CDF 및 기존 Gold는 변경하지 않았다.

14개 모두 전체 키와 컬럼이 기존 Gold와 일치했다. 각 표의 누락 및 추가 키 0, 모든 컬럼 불일치 0이다. 내보낸 파일 14개는 기존 Gold와 SHA-256도 모두 같았다. 파일 지문 대조는 전수 SQL 비교 뒤에 추가로 확인했으며 해당 해시 계산 시간은 본 실행의 elapsed_seconds에 포함하지 않았다. 컬럼 순서와 자료형, 정수와 문자열 및 날짜와 NULL을 대조했고 실수는 상대 및 절대 허용 오차 1e-12를 적용했다. 기간은 양쪽 합집합으로 확인했고 중복과 NULL 키는 사전에 거부했다. 결과 전체를 Python 객체로 가져오지 않고 정렬된 두 Parquet의 해당 월 또는 연도를 SQL로 읽어 FULL JOIN했다.

연간 청취자와 최대 계정 및 집중도는 사용자별 연간 기여에서 계산한다. 월별 숫자를 합치지 않는다. 미연결과 미확인 및 버전 분리, 참여 아티스트마다 횟수를 부여하는 정책을 유지했다. 이번 전체 대조는 기존 Gold와의 일치이며 기존 곡 식별 및 귀속 정책의 사실 정확성을 새로 확정한 것은 아니다. 독립 Python 기대값은 앞선 고정 표본 검증에서 유지했다.

전체 8GB build 시도의 실행 시간은 2724.415초였다. 이 중 연간 기여의 양방향 집합 검사는 465.73초 뒤 메모리 오류가 났다. 키 조인 방식과 16GB 구성으로 바꾼 뒤 같은 전체 기여 대조는 73.85초에 통과했다. SQL과 메모리 설정을 함께 바꿨으므로 한 변경만의 개선 비율로 해석하지 않는다. 통과한 모델 SQL의 변경을 거부하는 지문 검사를 거쳐 dbt 결과 상태로 실패 및 건너뛴 68개만 재실행했다. 성공 상태 노드의 순수 모델 실행 합은 1646.133초, 데이터 검사 실행 합은 1140.753초다. 실패한 검사 시간은 이 두 합에 포함하지 않고 전체 시도 시간에 포함한다.

성공 시도는 앞서 완료한 입력 사본을 복사해 재검증했다. 최초 Silver 및 사전 복사는 160.096초였고 그 실패 시도의 전체는 173.589초다. 세 시도의 실행 시간을 합치면 5430.716초이며 수정과 테스트 사이 대기 시간은 포함하지 않는다. 성공 시도 전체를 처음부터 입력을 복사한 처리 시간으로 표시하지 않는다.

기존 귀속 갱신의 649.68초는 14개 전체를 새로 만든 시간이 아니므로 이번 수치와 속도 비율로 비교하지 않았다. dbt run_results의 개별 모델 및 검사 시간은 결과의 node_seconds에도 남겼다. 같은 전체 입력의 두 번째 재생성은 수행하지 않았고 반복 실행 의미는 기존 표본에서 검증했다.

복사 표의 내용 지문 재검증과 체크포인트, 정리 및 대기를 포함한 별도 타이머 밖의 구간은 1081.177초다. 이 구간은 더 세분해 계측하지 않아 특정 연산의 CPU 시간으로 해석하지 않는다. 표의 전체 시간은 실제 경과 기준이며 구간별 합과 함께 남겼다.

## 실패와 검사

첫 전체 시도는 입력 복사 뒤 dbt debug에서 실패했다. 작은 전체 설정 통합 검사도 같은 temp_directory 권한 오류를 검출했다. settings 순서 변경만으로는 build의 다음 커서에서 다시 실패했다. 설치된 어댑터의 연결 생성 및 커서 초기화 코드를 확인해 임시 경로를 config_options로 옮겼다. 외부 파일 접근 차단은 유지했다. 실패 출력과 로그를 보존하고 새 경로에 닫힌 준비 DB를 복사해 재검증했다.

빠른 회귀 108개가 39.34초에 통과했다. 새 비교 검사는 큰 정수의 1 차이, 누락과 추가 키, 중복 및 NULL 키, NULL과 자료형, 실수 허용 오차 및 NaN과 무한대, 기간별 비교 및 경로 중첩, 원래 프로젝트 불변과 실행 중 및 변조된 준비 자료 재사용 거부를 포함한다. 전체 물리 설정과 실패 후 선택 재실행의 실제 표본 통합 pytest 2개도 89.32초에 통과했다. 20개 테이블 생성과 두 build 및 문서, 14개 기존 기대값 대조, 의도한 검사 오류와 하류 건너뛰기 뒤 선택 재실행 및 전체 169개 상태 합산을 확인했다. 연간 기여의 중복 행은 전용 유일성 검사로 계속 탐지했다. 기존 Spark 정제를 바꾸지 않아 Spark 검사를 새로 실행하지 않았다.

전체 실행의 모든 모델과 검사 노드는 성공했고 문서에 source 4개와 모델 24개, 최종 마트 14개 및 컬럼 150개의 설명과 부모 관계가 대응했다. 원래 Delta 버전과 파일 정보, 기존 자료의 SHA-256, 복사 DB의 내용 지문 및 실행 프로젝트 지문도 유지됐다. `completed=true`, `source_unchanged=true`, `copied_tables_unchanged=true`, `production_applied=false`, `promotion_ready=false`다. 재현과 측정 경계는 [전체 실행 절차](../dbt_full.md)를 따른다.

별도 사례 검수에서는 2026년 8월의 RM 공식 ID 58f1e354-ecbc-4fd3-aa25-97eb1d9bd8b9가 61,608회와 585계정, 청취 수 순위 2위와 청취자 순위 288위 및 최대 계정 비중 0.20404817556161536으로 그대로였다. Radiohead도 20,047회와 3,030계정, 청취자 순위 2위가 같았다. 이름 RM이 붙은 다른 공식 ID는 3회와 1계정으로 분리돼 있어 이름만으로 합치지 않았다. 이 수치는 기존 공식 귀속 범위와 해당 월의 결과이며 다른 범위의 이전 집중도 사례와 직접 비교하지 않는다.

source 설명에 남은 표본 전용 표현은 고정 입력 범위로 정정하고 모델 설명도 같은 기준으로 보완했다. 실제 계산에 사용한 project 사본은 지문 그대로 보존했다. 별도 documentation-project로 docs만 다시 생성해 source 4개와 모델 24개 및 최종 컬럼 150개 설명을 확인했다. 데이터 모델을 다시 실행한 것은 아니며 이 추가 문서 생성 시간은 본 실행 시간 밖이다.

## 남은 범위

전체 데이터의 dbt 생성과 기존 Gold 전수 대조는 이 별도 경로에서 완료했다. 운영 조회 대상 교체와 GX 연결, 영향 기간의 Gold 증분 및 삭제 반영, 카탈로그 확대와 연속 운영 및 복구 검증은 별도다. 공식 곡 연결과 귀속의 미확인 후보 검수도 계속 남아 있다.
