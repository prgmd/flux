# 중복 제거 키 실측 (2026-09-07)

명세 6.3의 중복 제거 키는 `user_name` + `listened_at` + `recording_msid`다.
코드로 옮기기 전에 그 키가 실제 데이터에서 어떻게 작동하는지 확인한 결과다.

대상은 Bronze 155,713,649행 전수다.

## 키가 모든 행에서 작동한다

| 키 컬럼 | 빈 값 |
| --- | ---: |
| `user_name` | 0 |
| `listened_at` | 0 |
| `recording_msid` | 0 |

**하나도 비어 있지 않다.** 키 컬럼에 빈 값이 있으면 그 행들은 서로 구분되지 않고
한 덩어리로 뭉개지는데, 그런 일이 없다.

## 중복은 2.90%다

| 항목 | 값 |
| --- | ---: |
| 전체 행 | 155,713,649 |
| 서로 다른 키 | 151,192,624 |
| 중복인 키 | 1,737,739 (1.15%) |
| 지워질 행 | **4,521,025 (2.90%)** |
| 한 키의 최대 행 수 | 8 |

## 중복이 어디서 오는가

| 성격 | 키 |
| --- | ---: |
| 덤프를 걸친 중복 | **1,737,739 (100%)** |
| 한 덤프 안의 중복 | **0** |

**한 덤프 안에는 중복이 하나도 없고, 전부 덤프를 걸친다.**

이것이 뜻하는 바가 둘이다.

1. **덤프 자체는 깨끗하다.** ListenBrainz가 하루치를 내보낼 때 중복을 넣지 않는다
2. **연속한 증분 덤프가 겹친다.** 같은 청취가 이틀치 덤프에 들어 있다

2번이 중요하다. 증분 덤프를 여러 날 모아 적재하는 구조에서는 **중복 제거가
선택이 아니라 필수**라는 뜻이다. 하루씩만 보면 중복이 없어 보이므로,
하루치로 검증하고 넘어가면 이 문제를 놓친다.

## 내용이 다른 중복이 17.9%다

| 항목 | 키 |
| --- | ---: |
| 중복인 키 | 1,737,739 |
| 그중 내용이 서로 다른 키 | **310,285 (17.9%)** |

82.1%는 완전히 같은 문서라 아무 쪽을 남겨도 결과가 같다.
**나머지 17.9%는 어느 쪽을 남길지 정해야 한다.**

무엇이 다른지는 `2026-09-07-duplicate-content-diff.md`에 있고,
그 결과로 정한 규칙은 `docs/deduplication.md`에 있다.

## 재현

```
docker run --rm -m 12g -v <데이터 루트>:/data \
  -e FLUX_STORAGE_ROOT=file:///data ... flux-spark \
  python scripts/investigations/measure_duplicates.py
```

결과는 데이터 루트의 `measurements/duplicates.json`에 있다.

내용 비교는 `raw_json` 원문 대신 `md5` 지문으로 했다.
1억 5571만 개의 긴 문자열을 그대로 셔플하면 네트워크가 병목이 된다.
